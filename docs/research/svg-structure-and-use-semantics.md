# SVG Structure and Use Semantics Research

Status: implementation evidence for ISS-107

Last verified: 2026-07-15

## Primary sources

[SVG 2 Document Structure](https://www.w3.org/TR/SVG2/struct.html) defines `defs` as a container for referenced content and `symbol` as a reusable graphical template. It defines `use` as a reference that instantiates a copy in the rendering tree while retaining correspondence to the referenced source subtree. The unqualified `href` attribute takes precedence over legacy `xlink:href` when both are present.

[SVG 2 Rendering Model](https://www.w3.org/TR/SVG2/render.html) distinguishes the authored document tree from the rendering tree. A `defs` element, a source `symbol`, and their descendants do not render directly, while the instance generated by `use` can contribute to rendering.

The `use` definition makes `x` and `y` supplemental translation geometry properties. Its `width` and `height` affect a referenced `svg` or `symbol` viewport and otherwise have no effect. Presentation properties on the use host participate in inheritance into the instance tree, while selector matching for corresponding elements remains based on the source document state.

## Semantic model

svgdiff indexes the authored structure once and derives a bounded rendered-subject plan from it. Authored nodes retain IDs, generated fallback identities, source offsets, parentage, and declaration facts. Rendered subjects add an optional instance context containing the source definition ID and the ordered use-host path. This avoids both conflating several placements and manufacturing cloned source declarations.

The admitted target slice is same-document local fragments resolving to supported basic graphics, `g`, `svg`, `symbol`, or nested `use`. Existing cycle detection and conservative transitive expansion limits run before renderer parsing. Missing, external, wrong-kind, malformed, unsupported-length, and invalid viewport references are diagnosed rather than treated as empty visual equality.

Use-host cascade and inheritance are evaluated by inserting the use host into the rendered ancestry before traversing the corresponding source subtree. Source-node stylesheet matches remain preserved. A changed definition declaration therefore stays definition-owned while its affected-subject set contains every rendered instance ID.

Transforms are composed in rendered ancestry order. Supplemental use translation is applied after the authored use transform in the engine's transform chain. A referenced `svg` or `symbol` establishes an instance viewport from use width and height, target viewBox, and preserveAspectRatio. Symbol overflow clipping, arbitrary structural stacking changes, external documents, scripts, animation, and interactive instance-tree behavior remain outside this slice.

## Renderer evidence

Six Chromium fixtures cover repeated shape instances, use-host inheritance, a symbol viewport, nested use, a transformed use, and a nested transformed use. Repeated placement, inheritance, symbol viewport mapping, and untransformed nesting are exact against the pinned raw renderer. The two cases combining a use transform with nonzero supplemental translation diverge and are bound to `renderer_use_transform_raster_unproven` in renderer-conformance profile `/18`.
