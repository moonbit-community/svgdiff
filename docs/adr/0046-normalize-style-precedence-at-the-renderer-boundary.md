# Normalize style precedence at the renderer boundary

`mizchi/svg@0.2.1` applies conflicting presentation attributes and inline declarations in XML attribute order, and no released package contains the open upstream fix. Production will privately normalize only renderer-input copies. When the existing supported inline declaration parser is complete, every overlapping presentation-attribute value is replaced with the XML-escaped effective inline value before renderer parsing. Original SVG strings remain authoritative for Source Semantics, Source Spans, Changed Facts, Diagnostics, resource admission, and presentation. Incomplete or unsupported inline syntax is not rewritten and retains `renderer_style_precedence_unresolved`, so the adapter cannot turn uncertainty into complete equality.

The adapter is part of the rendering implementation, so producers identify it as `svgdiff/style-precedence-normalizer@1+mizchi/svg@0.2.1`; the accepted claim advances to `svgdiff-renderer-conformance-profile/2`. Structured Report field meanings remain schema `1.4`. JSON Schema therefore constrains renderer identities as non-empty opaque strings, while the versioned consumer compatibility policy accepts known old and new identities and rejects unknown ones. This keeps renderer and conformance versioning independent from report shape without invalidating reports produced before the adapter.
