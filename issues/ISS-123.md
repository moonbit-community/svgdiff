## Description
Move the accepted one-to-one, insertion, deletion, split, merge, and safe many-to-many Subject Alignment shapes from unit-test-only evidence into the production benchmark corpus. Make each expected relationship and side cardinality machine-checkable without treating authored IDs, source order, or array positions as cross-document identity.

## Design
Add dedicated corpus pairs for deletion, split, merge, and an exact repeated-subject many-to-many reorganization; reuse existing curated pairs for one-to-one correspondence and insertion. Extend corpus smoke expectations with a `required_subject_alignments` array containing only relation, before/after cardinality, and an optional accepted basis. The corpus validator must execute the production CLI and require every declared alignment expectation, then require benchmark-wide coverage of `(1,1)`, `(0,1)`, `(1,0)`, `(1,N)`, `(N,1)`, and `(N,N)` for `N > 1`.

Keep the many-to-many fixture inside the accepted safe boundary: equal-cardinality, exact rendered and reportable source-semantic duplicates whose IDs and order change but whose members cannot be paired. It must produce one `exact_visual_equivalence_class` with no pairwise positional meaning. Do not manufacture a mixed-change N-to-M aggregate: the current report cannot enumerate its per-member source differences without pair identity, so such clusters must retain conservative one-to-one and presence fallbacks until a future aggregation contract exists.

Add hidden alignment-reference annotations for the representative corpus cases and validate them separately from visual main-change, ranking, region, and cause labels. Add ordinary human annotations for every new curated pair so the existing text-only Agent benchmark continues to cover the entire corpus. Update reproducible benchmark expectations from observed production reports; do not weaken existing accuracy, safety, localization, cause, or determinism thresholds.

No module or Structured Report schema version changes are expected unless a fixture exposes a production defect. Corpus and annotation artifacts remain versioned evaluation inputs, not report semantics.

## Acceptance Criteria
- [x] The production corpus contains representative one-to-one, insertion, deletion, split, merge, and safe many-to-many pairs.
- [x] Corpus expectations validate relation, side cardinalities, and optional basis through the installed production CLI.
- [x] Benchmark-wide validation proves all six accepted cardinality shapes are present.
- [x] The many-to-many fixture emits one exact equivalence class, retains every endpoint, and does not imply pairwise array identity.
- [x] Split and merge fixtures retain explicit set membership and do not degrade into insertion/deletion noise.
- [x] Mixed-change or unequal-cardinality repeated clusters are not silently collapsed by this validation work.
- [x] Hidden alignment-reference annotations are structurally validated and never exposed to the evaluated Agent.
- [x] Every added corpus case has main-change, ranking, region, and actual-cause annotation coverage.
- [x] Agent/evaluation baselines are recomputed from production reports without weakening existing perfect safety and recall gates.
- [x] Relevant MoonBit, corpus, annotation, benchmark, determinism, schema, CLI, renderer, and performance gates pass.
