## Description
Validate the M5 universal claim that every adopted dynamic, `foreignObject`, beyond-sRGB, platform, or cross-renderer capability has both a separately versioned profile identity and a pinned environment. The current adopted set is empty, so the gate must prove that fact from accepted decision artifacts and reject any silent or incomplete adoption rather than pretending an advanced capability exists.

## Design constraints
- Inventory exactly the advanced families named by the M5 gate: platform-native fonts, beyond-sRGB color, multi-renderer comparison, scripts, interaction, animation, and foreign content.
- Derive current adoption from both the M5 non-goal manifest and each governing decision artifact's product implementation flag.
- Require each family to expose machine-readable future identity formats and complete environment/input requirement groups even while unadopted.
- If a family becomes adopted, require a concrete profile instance and pinned environment instance in addition to implementation evidence; a reserved format string is not an adopted instance.
- Keep the current adopted-capability set explicitly empty and distinguish this universal gate from implementing or accepting an advanced profile.
- Do not change product code, public APIs, Structured Report Schema, profile or policy identities, CLI behavior, fixtures, dependencies, default CI, or release assets.

## Acceptance Criteria
- [x] A versioned gate manifest inventories the seven M5 advanced-capability families and their adoption evidence.
- [x] Every family identifies its decision artifact, product implementation flag, future profile identity fields, environment requirement fields, and corresponding non-goal capability.
- [x] The validator proves the current adopted set is empty from both evidence sources.
- [x] The validator rejects missing families or fields, stale adoption state, fabricated current instances, and an adopted status without implementation, concrete profile, or pinned environment evidence.
- [x] Existing decision and M5 non-goal validators pass without adopting any advanced capability.
- [x] A production CLI probe retains only the current static sRGB single-renderer profile and contains no advanced profile instance.
- [x] Current scope, renderer guidance, roadmap, and documentation index state the adopted-set and future admission rule precisely.
- [x] Only the exact M5 adopted-capability checklist item is checked; deferred advanced implementations and terminal gates remain unchecked.
- [x] Product code, public interfaces, Schema, profile/policy identities, CLI behavior, fixtures, dependencies, default CI, and release assets remain unchanged.
- [x] Focused gate tests, `moon info`, `moon fmt`, strict native check, full native tests, tracker generation, and `git diff --check` pass.
