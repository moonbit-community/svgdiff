## Description
ISS-090 reports exact authored transform lists and cumulative affine matrix changes, but deliberately assigns no raw coefficient score. A text-only agent therefore knows that a transform changed without receiving machine-readable translation, rotation, scale, skew, or non-decomposable residual effects and cannot order changes from the same transform-effect domain by their degree.

## Design
Independently apply a deterministic two-dimensional QR/unmatrix decomposition to the before and after cumulative matrices, following the component model standardized by [CSS Transforms Level 1](https://www.w3.org/TR/css-transforms-1/#decomposing-a-2d-matrix). Decompose each matrix in viewport coordinates into translation, rotation, signed axis scale, and X skew. Compare translation directly in viewport CSS pixels and normalize rotation and skew deltas to `[-180, 180)` degrees. Use one reflection convention: a negative determinant is retained in the Y scale. Independent canonical decomposition keeps translation tied to the observable CTM origin and avoids the origin-dependent translation component produced by decomposing `after * inverse(before)`.

Emit a separate Atomic Difference for every non-neutral effect under exact domains `geometry.transform.translation`, `geometry.transform.rotation`, `geometry.transform.scale`, and `geometry.transform.skew`. Retain signed component values and explicit nonnegative same-domain magnitudes in a tagged `TransformEffectMagnitude`: translation uses CSS-pixel X/Y values and Euclidean norm; rotation and skew use signed and absolute degrees; scale uses signed X/Y factors and the maximum absolute paired delta. Do not turn these units into a cross-domain score.

If either linear transform is singular, retain any independently valid translation effect and emit `geometry.transform.residual_matrix` for a changed linear part with exact before/after affine coefficients and determinants but no coefficient-distance magnitude. A pair of successful decompositions has no residual item. Component differences share the cumulative transform Changed Facts, Subject Alignment, Visual Event, renderer observation, and conservative regions established by ISS-090.

Adding a structured transform magnitude changes the public MoonBit record surface and Structured Report shape. Allocate the required module and Schema versions. Because transform-effect domains need component-specific same-domain ordering inputs, allocate a new ordering policy rather than changing `v1_domain_lexicographic` in place. Record the coordinate-space, reflection, singularity, units, and no-scalar boundary in ADR 0047 and current contracts.

## Acceptance Criteria
- [x] Before and after cumulative matrices are independently decomposed in viewport coordinates, and identity changes emit no component effects.
- [x] Deterministic decomposition reports translation, shortest signed rotation delta, signed X/Y scale values, and shortest signed X-skew delta and reconstructs representative invertible matrices.
- [x] Reflections, rotations across the degree wrap boundary, and combinations of non-commuting transforms have pinned results.
- [x] Singular or non-invertible changes emit an exact residual matrix effect without a raw coefficient-distance score.
- [x] Every non-neutral component is a separate deterministic Atomic Difference linked to the cumulative transform cause and owning Visual Event.
- [x] Tagged transform magnitudes expose direction and explicit units while preserving numeric zero versus absence.
- [x] Same-domain ordering uses component-appropriate nonnegative magnitude fields under a newly allocated policy and remains incomparable across transform domains.
- [x] Current contracts, ADR 0047, canonical and Agent examples, evaluation annotations, compatibility artifacts, and version identities describe the implemented boundary.
- [x] Unsupported CSS transforms, viewport mapping, transformed-boundary displacement, and Impact Assessment remain outside this item.
- [x] Relevant MoonBit and repository validation gates pass.
