# ISS-122: Match repeated subjects as semantic equivalence classes

## Description
Stop manufacturing source-order one-to-one identity for repeated subjects that current visual or structural evidence cannot distinguish. Represent exact rendered duplicates as set-to-set equivalence classes and use source-order-independent semantic subtree signatures before authored-ID or structural-path fallback for structural subjects.

## Design
Keep every accepted alignment a partition of its inventory: no subject appears in two accepted alignments, and ambiguity remains explicit. After exact use-instance-path matching, collect equal-cardinality repeated direct rendered subjects with the same transform- and bounds-aware exact signature and the same currently reportable declaration, path-command, and transform-chain source semantics into one correspondence alignment. The source-semantic guard prevents a set alignment from hiding differences such as equivalent color spellings. Preserve every endpoint in source traversal order inside the set, but do not assert pairwise membership. Reuse exact score zero, tied candidate evidence, and null uncalibrated confidence. Unequal-cardinality or mixed-change rendered clusters retain the current deterministic one-to-one/fallback behavior until the next benchmark item specifies broader many-to-many invariants.

For source-structural subjects, compute a recursive semantic signature from SVG kind, order-independent attributes except authored `id` and known nonvisual metadata attributes, direct text content for text subjects, and ordered child signatures. Ignoring the subject's own ID and sibling ordinal lets renamed or reordered groups, text, use hosts, and resource definitions match by their source semantics; preserving child order avoids erasing stacking semantics. Equal-cardinality semantic classes become one set alignment, including the one-to-one case. When semantic signatures differ, retain authored-ID, structural-path, and stable-kind-order fallbacks so changed subjects remain traceable.

Allocate a distinct `structural_semantic_signature` score kind with candidate-only evidence. Do not call a repeated class unique, infer pairwise identity from array positions, use raw source order as semantic evidence, collapse insertions/deletions, align Visual Resources independently, or calibrate confidence.

## Acceptance Criteria
- [x] Equal-cardinality repeated rendered subjects with one exact visual and reportable source-semantic signature produce one set-to-set alignment rather than arbitrary source-order pairs.
- [x] Equivalent rendered subjects with different reportable source semantics retain their Atomic Differences instead of entering a multi-endpoint class.
- [x] The repeated rendered alignment retains every endpoint, exact zero score, tied counts, and null uncalibrated confidence.
- [x] Structural semantic signatures ignore authored IDs, sibling order, attribute order, and known nonvisual metadata while preserving kind, visual/source attributes, direct text, and child order.
- [x] Reordered or renamed structurally distinct groups align by semantic subtree rather than authored ID, path, or stable order.
- [x] Repeated structurally indistinguishable subjects produce one set alignment without pairwise identity.
- [x] Changed structural subjects still fall back to authored-ID/path/order evidence and remain traceable.
- [x] Existing use-instance, transform/geometry, insertion/deletion, split/merge, structural-difference, coverage, and deterministic behavior remains valid.
- [x] Documentation and Agent guidance prohibit interpreting set array positions as pairwise correspondence.
- [x] Module/schema/version archives, canonical examples, compatibility, and adversarial evidence cover the new score and set cardinality.
- [x] Relevant MoonBit, schema, compatibility, mutation, adversarial, determinism, Agent, CLI, package, release, renderer, and performance gates pass.

## Close Notes

Equal-cardinality repeated rendered subjects now form one `exact_visual_equivalence_class` only when their exact rendered signature and currently reportable declaration, path-command, and transform-chain source semantics all agree. The alignment retains every endpoint, score zero, tied cardinality, and null uncalibrated confidence without assigning pair identity. The source-semantic guard keeps equivalent authoring changes such as `red` to `#ff0000` in one-to-one alignments, where every Atomic Difference remains reportable. Multi-endpoint exact classes no longer manufacture a `document.structure` difference for identical inputs.

Source-structural subjects now align first by a recursive kind, attribute, text, and ordered-child signature that ignores unprefixed authored IDs, sibling position, attribute order, namespace declaration spelling, and unprefixed `aria-*`/`data-*` metadata. Renamed and reordered distinct groups therefore follow their subtrees, identical repeats remain one set, and changed subjects retain authored-ID, path, and stable-order fallbacks. Added ADR 0078, explicit non-pairwise Agent guidance, a canonical two-by-two report, and a `false_pair_identity` adversarial case.

Advanced the module to `0.5.14` and Structured Report schema to `1.34`, archived schema `1.33`, and kept renderer identity plus conformance profile `/25` unchanged.
