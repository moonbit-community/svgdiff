## Description
Add reproducible generative fuzzing across XML parsing, SVG semantic adaptation, renderer input, Structured Report JSON serialization, and hostile-source HTML escaping.

## Design
The current MoonBit test command has no coverage-guided fuzz mode. Add a fixed-seed production-CLI runner that generates supported, limited, malformed, and hostile-but-well-formed SVG pairs. Every case must traverse the release CLI, validate its report against the current JSON Schema, generate HTML, verify sandbox and escaping invariants, and record input/report/HTML hashes. Support arbitrary seeds, scalable case counts, and one-case replay. Run the smoke seed twice and require byte-identical result manifests. Do not describe this as coverage-guided fuzzing.

## Acceptance Criteria
- [x] Generated cases exercise successful and failed XML parsing.
- [x] Well-formed cases reach supported rendering and limited semantic-adaptation paths.
- [x] Every report validates against its declared current Schema.
- [x] Hostile source cannot break preview attributes, the JSON textarea, or the one-template-script boundary.
- [x] The runner records exact seed, case index, category, and deterministic hashes for replay.
- [x] A bounded smoke command runs twice with byte-identical results.
- [x] Documentation distinguishes generative smoke from coverage-guided fuzzing and states how to scale and replay it.

## Close Notes
Added a deterministic production-boundary fuzz runner with configurable seed, case count, and single-case replay. Four interleaved families exercise supported complete rendering, limited path and transform adaptation, malformed XML failed reports, and well-formed hostile source containing `textarea`, `iframe`, `script`, quote, and ampersand boundary content.

Every case runs through the native release CLI, validates the compact report with the current JSON Schema, checks analysis-status/exit-code agreement, generates the self-contained HTML report, verifies two empty-sandbox previews, escaped `srcdoc`, exactly one template script, and round-trips the embedded JSON textarea. Result artifacts retain input, report, and HTML SHA-256 hashes with exact seed and case index.

The bounded smoke gate runs seed `20260714` with 24 cases twice and requires byte-identical manifests, then replays one selected case. A separate 100-case seed completed with 50 complete, 25 partial, and 25 failed reports. Documentation explicitly states that this is reproducible generative fuzzing, not coverage-guided or sanitizer-guided fuzzing, and leaves resource budgets separate.

Verified the deterministic fuzz smoke and replay, a 100-case alternate seed, current Schema validation for every generated report, warning-clean native checks, all MoonBit tests, Python syntax, local Markdown links, and `git diff --check`.
