## Description
Until a released `mizchi/svg` package contains the inline-style precedence fix tracked by ISS-002, detect elements that declare the same supported property through both a presentation attribute and inline `style`. Such documents cannot safely use the dependency renderer as complete evidence.

## Design
Keep Source Semantics attribute-order independent. Add a conservative preflight Diagnostic affecting Computed Appearance and Rendered Evidence whenever supported inline-style and presentation-attribute properties overlap. This guard must not invent an Atomic Difference, but it must reduce the report to `partial` so renderer divergence cannot become false complete equality.

## Acceptance Criteria
- [x] Reordering conflicting `style` and presentation attributes produces no Source Semantics Atomic Difference.
- [x] Both orderings produce a renderer-conformance Diagnostic and a `partial` report.
- [x] The Diagnostic names only Computed Appearance and Rendered Evidence as affected layers.
- [x] The limitation and upstream dependency are documented.
- [x] Relevant MoonBit checks and tests pass.

## Close Notes
Added a conservative source preflight guard for every supported inline-style property that overlaps a presentation attribute on the same element. The normalized Source Semantics still reports no Atomic Difference across attribute reorderings, while the report becomes `partial` with `renderer_style_precedence_unresolved` affecting only Computed Appearance and Rendered Evidence. Documented the upstream-release limitation and verified the targeted regression plus native warning checks.
