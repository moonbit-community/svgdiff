# ISS-111: Implement explicit local raster resource bundles

## Description
Implement the roadmap's caller-supplied local resource-bundle slice without turning SVG locators into filesystem or network authority. Let library callers provide separate before/after opaque locator-to-byte mappings and let the CLI load only explicitly named resource files. Reuse the admitted bounded PNG/JPEG decoder, intrinsic evidence, image alignment, placement, magnitudes, and report provenance from ISS-110.

## Design
Expose an ordered `ResourceBundle` of `ResourceBundleEntry` values containing an opaque locator, an explicit media type, and bytes. Resolve an `image` href only by an exact match in the corresponding side's supplied bundle after trimming the authored locator. Do not normalize URLs or paths, infer base directories, percent-decode locators, follow redirects, open SVG-authored paths, or fetch the network. Data URLs keep their existing embedded-resource path.

Validate each bundle deterministically before comparison: locators must be nonempty external locators, duplicates are invalid, media types must be an admitted PNG/JPEG type, entry count and cumulative/per-entry byte sizes are bounded, and signatures plus decoder results must agree with the declared media type. Missing entries remain source-located partial coverage; invalid bundle configuration fails admission without serializing payload bytes. Keep before and after bundles separate so the same locator may intentionally identify different bytes on each side.

Add root APIs with and without cooperative controls. Add repeatable single-value CLI options `--before-resource RESOURCE_JSON` and `--after-resource RESOURCE_JSON`; these are the only additional files the CLI may read. HTML remains a presentation of the two original SVG sources and the report, not a resource transport surface.

## Acceptance Criteria
- [x] Root callers can compare with separate explicit before/after bundles, with an equivalent controlled API.
- [x] Exact opaque locator matching resolves supplied PNG/JPEG bytes through the existing bounded decoder and reports the same intrinsic and placement evidence as data URLs.
- [x] No engine path or network I/O, implicit base directory, URL normalization, MIME sniffing, or payload serialization is introduced.
- [x] Empty/duplicate/reserved locators, unsupported MIME, signature/decode failures, entry-count, per-entry-byte, cumulative-byte, dimension, and pixel limits have deterministic behavior.
- [x] A missing bundle entry is source-located partial coverage; invalid caller bundle configuration fails admission before ordinary comparison.
- [x] Repeatable single-value CLI resource options read only explicitly named files and retain exit status 2 for argument or I/O failures.
- [x] Focused tests cover per-side replacement under one locator, equivalence to data URLs, exact matching, missing/invalid entries, limits, deterministic ordering, controls, CLI parsing/I/O, and payload secrecy.
- [x] Scope, API, safety, resource, research, ADR, schema/version, and roadmap documentation describe the implemented boundary and deferred cross-resource behavior.
- [x] Relevant MoonBit and repository validation gates pass.
