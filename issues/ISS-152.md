## Description
Decide whether CoreText, DirectWrite/ClearType, GDI, browser text, or other platform-native font rendering modes can be supported Font Execution Profiles, or whether they remain outside canonical deterministic comparison. Preserve their possible value as renderer observations without allowing ambient fonts or platform state to weaken equality, completeness, or reproducibility claims.

This item records a product boundary. It does not implement a platform backend, load a system font, add a profile option, capture a new raster, change the Structured Report, or resolve the separate Phase 9 question of comparing one renderer with itself versus different renderers.

## Design constraints
- Distinguish canonical font execution from external observational/conformance evidence.
- Treat exact caller-supplied Font Resources separately from ambient system-font discovery and fallback.
- Enumerate every environment identity and state input that could affect a native observation; a platform name alone is insufficient.
- Do not claim that naming an OS build makes native pixels reproducible across hardware, display, process, or framework state.
- Preserve current browser-oracle and renderer-conformance authority boundaries.
- State permanent non-goals, permitted future roles, and explicit reconsideration gates.
- Do not add product code, native dependencies, module dependencies, report fields, CLI flags, default CI work, or release assets.

## Acceptance Criteria
