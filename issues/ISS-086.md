## Description
Publish release-mode native CLI archives and archive checksums for every supported operating-system and architecture pair.

## Design
Extend the existing release bundler rather than creating a second packaging format. Normalize hosted runner identities to `linux-x64`, `windows-x64`, and `macos-arm64`, preserve the Windows `.exe` suffix, and optionally archive the complete checksummed bundle as `.tar.gz`.

On a pushed `v<module-version>` tag, build and test each supported target, create its clean release archive, and capture the canonical determinism bundle from the packaged executable. Before publication, require byte-identical report bundles across all three targets, collect exactly three archives, generate archive-level `SHA256SUMS`, and publish the four assets through `gh release create --verify-tag`. Reject a tag that does not exactly match `moon.mod`; never create or move a tag from the workflow.

## Acceptance Criteria
- [x] Release packaging uses stable platform names and preserves the Windows executable suffix.
- [x] Every archive contains the executable, internal checksums, provenance, license, and dependency notices.
- [x] A tag must exactly equal `v<moon.mod version>` before any release asset is published.
- [x] The release matrix builds and tests Ubuntu 24.04 x64, Windows Server 2025 x64, and macOS 15 arm64.
- [x] Publication is gated on exact cross-platform canonical report bytes and a complete three-archive inventory.
- [x] GitHub Release assets contain all three archives plus archive-level `SHA256SUMS`.
- [x] Local release tests cover clean-source rejection, explicit dirty provenance, archive integrity, tag acceptance, and tag rejection.
- [x] Documentation states installation, verification, supported targets, trigger semantics, and remaining signing or reproducibility gaps.
