# ISS-113: Separate nonvisual metadata from visual differences

## Description
Keep purely nonvisual SVG metadata out of visual Atomic Differences and visual-coverage failures while preserving an explicit source-only audit path. Let ordinary comparison remain focused on visual semantics, but let callers separately inventory changes to descriptive element content and nonvisual extension/accessibility attributes with deterministic source provenance.

## Design
Treat the authored content inside SVG `title`, `desc`, and `metadata` elements as a nonvisual subtree for the static visual comparison. Preserve each outer element in the semantic document because its presence, attributes, and sibling position can still participate in the supported XML/CSS structure, but mask its inner content with equal-length whitespace before visual analyzers and the renderer see it. This prevents foreign metadata vocabulary, resource-looking descendants, and hidden shapes from fabricating visual subjects, unsupported-feature Diagnostics, or reference cycles while preserving UTF-16 Source Span offsets outside the subtree.

Do not globally declare `aria-*` or `data-*` attributes visually inert. Their raw attribute values are nonvisual metadata, but supported CSS attribute selectors can make them causal inputs to a visual computed result. Ordinary comparison may therefore report the resulting paint/geometry consequence without allocating a metadata Atomic Difference.

Add a separate root `audit_nonvisual_metadata` operation and public source-audit records. Inventory the exact authored inner content of outermost SVG `title`, `desc`, and `metadata` elements plus unprefixed `aria-*` and `data-*` attributes outside those captured subtrees. Identify facts by a deterministic namespace-aware element path using same-qualified-name sibling ordinals. Align facts by kind, path, and name; report changed, inserted, and deleted facts with before/after UTF-16 spans. The audit has its own version, status, parse Diagnostics, and JSON serialization and never mutates or embeds itself into Structured Report.

## Notes
- This is not a byte-for-byte XML diff, full source-tree audit, accessibility conformance checker, or semantic RDF comparison.
- The audit intentionally records exact authored metadata values. Formatting within captured descriptive content may therefore be source-visible even when a downstream metadata consumer would normalize it.
- `id`, `class`, `style`, resource references, namespace declarations, and unknown attributes are not silently classified as nonvisual metadata.
