# ISS-049: Report encountered renderer capability gaps

## Description
Make renderer limitations encountered by the current inputs directly observable as structured capability metadata instead of requiring agents to infer them from Diagnostic code strings.

## Design
Add an additive `renderer_capability_gaps` array to current reports. Each record has a stable capability ID, `guarded` or `unavailable` support status, and the Diagnostic IDs that establish the gap. Derive it centrally from renderer-specific Diagnostics after coverage proof. Emit only gaps encountered by the current comparison; an empty array is not a global renderer support claim. Keep the field optional in JSON Schema `1.0` for older-report compatibility while current producers always emit it.

## Acceptance Criteria
- [x] Public report types and canonical and compact JSON expose structured renderer capability gaps.
- [x] Every current renderer-specific Diagnostic maps to one stable capability ID and support status.
- [x] Multiple Diagnostics for one capability merge without losing Diagnostic references.
- [x] Non-renderer analyzer limitations do not become renderer capability gaps.
- [x] Complete and failed reports emit an empty array when no renderer gap was encountered.
- [x] JSON Schema `1.0` remains backward-compatible with older reports.
- [x] Agent and current-contract documentation define encountered-only semantics.
