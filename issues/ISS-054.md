## Description
Generate a current-host native release bundle containing checksums, provenance metadata, the project license, and complete notices for every resolved production dependency.

## Design
Build the existing release executable and package it with machine-verifiable SHA-256 digests, transparent project-owned provenance, the Apache-2.0 text, and notices derived from a checked-in dependency manifest. Refuse dirty release inputs by default while permitting an explicit dirty development bundle whose provenance records that state. Do not claim signing, SLSA conformance, cross-platform reproducibility, or publication.

## Acceptance Criteria
- [x] The checked-in dependency manifest covers every direct and transitive package in `moon tree` with version, relationship, repository, license, and packaged-license evidence.
- [x] A release command builds a platform-named native bundle and includes an executable, `LICENSE`, dependency notices, provenance, and checksums.
- [x] Provenance records the artifact digest, source revision and dirty state, toolchain, target, build command, resolved dependencies, and report contract identities.
- [x] Release generation rejects dirty source by default and never labels an explicitly allowed dirty bundle as clean.
- [x] A deterministic test verifies the executable, every checksum, license copy, notice coverage, dependency resolution, and provenance fields.
- [x] Documentation distinguishes locally generated release evidence from signing, publication, SBOM, and cross-platform release guarantees.

## Close Notes
Added a versioned seven-package dependency manifest and a current-host native release bundler. Each bundle contains the release executable, the complete project Apache-2.0 text, generated versioned third-party notices, transparent project-owned provenance, and SHA-256 digests for every other bundled file. Dependency generation requires exact coverage of the unique `moon tree` packages and discloses the three resolved archives that omit a package-local license file.

The provenance records the executable digest, Git revision and dirty state, MoonBit toolchain, native OS and architecture, build command, all resolved dependencies, and module, report, renderer, conformance, and ordering identities. Clean source is required by default; the explicit development override is tested with an untracked marker and must serialize `source.dirty: true`.

Documented that these are unsigned local packaging facts rather than publication, signing, SLSA, SBOM, hermeticity, reproducibility, or cross-platform guarantees. Verified generated interfaces and formatting, warning-clean native checks, all 97 MoonBit tests, shell syntax, CLI and version integration, the complete release bundle and checksums, deterministic compatibility decisions, JSON syntax, local Markdown links, and `git diff --check`.
