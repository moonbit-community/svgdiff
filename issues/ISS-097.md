## Description
The engine currently resolves presentation attributes and a narrow inline `style` subset by overwriting declarations in extraction order. Stylesheets, `!important`, specificity, and explicit source-order comparison remain guarded, so the implementation has no reusable CSS cascade model and cannot safely accept matched stylesheet declarations later.

## Design
Introduce one private in-process cascade module whose small interface selects the winning declaration for each supported visual property from already applicable candidates. A candidate retains its exact `DeclaredVisualFact`, importance, origin, selector specificity, and document source order. The module implements author-origin SVG/CSS precedence: importance first, then inline specificity, selector specificity, and source order; presentation attributes participate as zero-specificity author declarations ordered before author stylesheets.

Inline-style and presentation-attribute adapters produce candidates through this seam instead of overwriting facts directly. Parse a stylesheet into source-located rules and declaration candidates, including selector text and specificity, but do not decide whether a rule matches an element here. The next roadmap item owns selector matching and will supply the applicable rule candidates. Until that matcher exists, encountered stylesheets remain explicitly partial rather than affecting computed appearance.

This separation makes the cascade a deep pure-computation module: callers and tests know only candidate construction and winner selection, while priority comparison, duplicate handling, `!important` parsing, deterministic ordering, and provenance remain local to its implementation.

## Acceptance Criteria
- [x] One private cascade module selects supported property winners from applicable declaration candidates.
- [x] Candidates retain exact authored value, normalized declared value, declaration origin, Source Span, importance, specificity, and source order.
- [x] Presentation attributes participate as zero-specificity author declarations before stylesheet and inline declarations.
- [x] Inline declarations outrank non-important stylesheet and presentation declarations independently of XML attribute order.
- [x] `!important` outranks normal author declarations; specificity and then source order break ties within the same importance.
- [x] Duplicate declarations in one inline block or rule follow importance and source order rather than extraction-time overwrites.
- [x] Stylesheet rules and supported declarations are parsed with exact selector/declaration provenance and deterministic specificity, without claiming that selectors match yet.
- [x] Existing presentation/inline source and computed behavior routes through the cascade module without losing provenance.
- [x] Renderer-input style normalization consumes the same winning inline/presentation declaration and preserves original sources.
- [x] Encountered stylesheets remain guarded until selector matching supplies applicable candidates; no stylesheet can imply false complete equality.
- [x] Focused MoonBit and browser-conformance cases cover origin, importance, specificity, and source-order precedence.
- [x] Current contracts, ADRs, evaluation artifacts, compatibility/version identities, and the roadmap describe the implemented seam and remaining selector boundary.
- [x] Relevant MoonBit and repository validation gates pass.
