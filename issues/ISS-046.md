## Description
Give the renderer conformance claim its own stable profile identity instead of inferring it from JSON Schema or renderer package versions.

## Design
Add `renderer_conformance_profile_id` to the canonical Comparison Profile and emit `svgdiff-renderer-conformance-profile/1`. Record the same ID in conformance baselines and CLI version output. Keep the field optional in JSON Schema `1.0` so older valid reports remain compatible, while current producers always emit it.

## Acceptance Criteria
- [x] Comparison Profile records an independent renderer conformance profile ID.
- [x] Current canonical and compact JSON emit the ID.
- [x] Conformance baseline and disposition validation require the same ID.
- [x] CLI `--version` exposes the ID separately from schema and renderer versions.
- [x] JSON Schema `1.0` remains backward-compatible with older reports.
- [x] Upgrade and public API documentation define independent version triggers.

## Close Notes
Added `svgdiff-renderer-conformance-profile/1` to current Comparison Profiles, canonical and compact reports, CLI version output, conformance baselines, and divergence dispositions. Schema `1.0` accepts the additive field without requiring it, preserving older valid reports. Validation rejects profile mismatches, and ADR 0034 plus current-contract and upgrade documentation define the independent version boundary.

Verified with 94 MoonBit tests, CLI and installation integration tests, renderer disposition positive and mismatch cases, all evaluation scripts, and an exact reproduction of the 15-case Chromium renderer-conformance baseline.
