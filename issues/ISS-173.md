## Description
Validate the fourth terminal acceptance claim by composing the current deterministic-output, installation, hostile-input boundary, compatibility/versioning, and supported-environment release evidence into one explicit operational gate.

## Design constraints
- Keep the claim scoped to the documented local CLI/library threat model and the exact supported native matrix.
- Preserve the distinction between deterministic report bytes and reproducible behavior; do not claim bit-identical executables or cross-toolchain builds.
- Treat fixed admission, no implicit I/O or scripts, unsafe-reference rejection, deterministic fuzz/adversarial coverage, and sandboxed HTML as the hostile-input boundary.
- Retain the documented absence of process isolation, hard arbitrary-input time/memory enforcement, exhaustive fuzz proof, signing, notarization, SBOM/SLSA attestation, and unauthenticated-service safety.
- Validate the real CI/release matrix definition while stating that local comparator controls do not emulate three operating systems.
- Do not change product code, public APIs, Structured Report Schema, profiles, policies, dependencies, supported targets, release artifacts, or security claims unless a separate defect is verified.

## Acceptance Criteria
- [x] A versioned terminal gate separates deterministic, installable, hostile-input, versioned, and supported-environment reproducibility obligations.
- [x] Every obligation names concrete controls, authorities, executable suites, and exact non-guarantees.
- [x] Machine validation rejects missing obligations, controls, suites, evidence, environment entries, workflow bindings, or security boundaries.
- [x] Installation and current-host archive tests exercise the production release binary, checksums, provenance, licenses, notices, direct PATH invocation, and deterministic reinstall.
- [x] Determinism, compatibility, version identity, fuzz, adversarial, resource-limit, reference-safety, and HTML isolation gates pass.
- [x] CI and release workflows bind Ubuntu 24.04 x64, Windows Server 2025 x64, and macOS 15 arm64 to native release tests and exact canonical report comparison.
- [x] Operational, security, release, determinism, roadmap, and documentation-index texts state the exact terminal claim and limitations.
- [x] Only the fourth terminal checklist item is checked; calibrated Impact, font, and deferred implementation items remain unchanged.
- [x] `moon info`, `moon fmt`, strict native check, full native tests, tracker generation, and `git diff --check` pass.
