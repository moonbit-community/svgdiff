# ISS-002: Make style precedence independent of attribute order

## Description
`mizchi/svg@0.2.1` applies presentation attributes and inline `style` in XML attribute order. The equivalent rects `<rect style="fill:red" fill="blue">` and `<rect fill="blue" style="fill:red">` therefore resolve to blue and red respectively, although inline style should win in both cases. The declared-fact layer correctly normalizes both sources to the same effective inline declaration, so relying on the current renderer without a guard can make formatting-only attribute reordering alter Rendered Evidence or can hide the renderer divergence behind a false complete equality result.

Runtime reproduction on 2026-07-13 printed `0,0,255,255` for the style-first input and `255,0,0,255` for the style-last input.

## Design
Establish a conformance boundary for presentation-attribute versus inline-style precedence. Prefer an upstream dependency fix if practical; otherwise normalize or adapt inputs privately before computed/rendered analysis. The Source Semantics model must remain attribute-order independent, and any unresolved renderer mismatch must reduce coverage through a Diagnostic rather than becoming equality.

## Acceptance Criteria
- [ ] A regression test proves that reordering conflicting `style` and presentation attributes does not change Computed Appearance or Rendered Evidence.
- [ ] The two inputs produce no Source Semantics Atomic Difference because their effective declared facts are identical.
- [ ] The comparison engine does not report `complete` equality while its renderer produces different pixels for the two semantically equivalent inputs.
- [ ] The chosen upstream fix, private normalization, or temporary coverage Diagnostic is documented with its conformance limitations.
- [ ] Relevant MoonBit checks and tests pass.
