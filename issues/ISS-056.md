## Description
Check in production-generated Structured Report examples for the core text-only agent interpretation cases and keep them synchronized with the CLI and JSON Schema.

## Design
Reuse curated SVG inputs for equivalent spelling, tiny numeric change, salient change, insertion, deletion, resource change, and partial coverage. Generate examples only through the release CLI. Validate every generated and checked-in report against the current Schema's complete used assertion vocabulary, reject unsupported future Schema keywords, assert case-specific semantics from a manifest, and require byte-identical regeneration.

## Acceptance Criteria
- [x] Checked-in examples cover equivalent spelling, tiny numeric deltas, salient changes, insertion, deletion, resources, and partial coverage.
- [x] Every example is generated by the production CLI from named SVG sources.
- [x] Every generated and checked-in example validates against the current report Schema.
- [x] A versioned manifest asserts the expected status, domains, computed relations, Diagnostics, and distinguishing numeric evidence.
- [x] Regeneration is byte-deterministic and fails when checked-in examples drift.
- [x] Agent-facing documentation links to the canonical examples and explains their scope.

## Close Notes
Added seven canonical production-CLI reports covering equivalent color spelling, a tiny numeric geometry delta, a salient fill change, subject insertion, subject deletion, a resource-mediated gradient change, and unsupported partial coverage. A versioned manifest fixes each source pair and asserts exact status, domains, computed relations, Diagnostic codes, and distinguishing raw magnitude conditions. Regeneration runs twice and requires byte identity with the checked-in examples.

Added a project Schema validator for the complete assertion vocabulary currently used by `svgdiff-report.schema.json`; it rejects future unsupported keywords rather than silently skipping them. Negative controls prove rejection of missing required fields, invalid nullable numbers, and invalid nullable facts. `mizchi/jsonschema@0.8.0` was not adopted because its current parser treats the Schema's `type` unions as unconstrained and its declared repository URL does not resolve.

The first real validation exposed a producer/Schema mismatch: derived MoonBit JSON omitted required nullable fields. Added explicit serializers for the four affected report records so unavailable magnitudes, absent authored IDs, absent before/after Changed Facts, and absent Subject Alignment IDs serialize as JSON null. Added `nullableDeclaredFact` to Schema `1.0` as an erratum matching the already-public optional MoonBit type. No conforming report meaning changed, so this does not allocate a new schema identity.

Verified generated interfaces and formatting, warning-clean native checks, all 102 MoonBit tests, CLI integration, the report-only Agent harness, benchmark thresholds, curated corpus, deterministic adversarial and compatibility suites, all seven Schema examples and validator negative controls, version identities, JSON syntax, local Markdown links, and `git diff --check`.
