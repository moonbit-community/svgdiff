## Description
Detect embedded raster color metadata and sample encodings that fall outside the fixed v1 sRGB profile. Replace the current generic raster-variant outcome with precise coverage Diagnostics for embedded ICC or other explicit color-profile metadata and for HDR or high-bit-depth content.

The engine must preserve exact source evidence and refuse to reinterpret, clip, or silently decode out-of-profile pixels as ordinary sRGB. CSS Display-P3 and other out-of-profile authored colors remain covered by the existing `color_profile_unsupported` Diagnostic.

## Design constraints
- Keep the v1 Comparison Profile fixed to deterministic sRGB; do not add color conversion, tone mapping, display-profile guessing, or platform color management.
- Detect PNG `iCCP`, non-default `gAMA`/`cHRM`, `cICP`, `mDCv`, `cLLi`, and sample depth above the admitted 8-bit slice.
- Detect JPEG ICC APP2 payloads and sample precision above the admitted 8-bit baseline slice.
- Treat PNG `sRGB` as explicit in-profile metadata, not a limitation.
- Preserve the exact `href` Source Span, compact encoded hash evidence, placement facts, and resource identity for both data URLs and explicit resource bundles.
- Emit `embedded_raster_color_profile_unsupported` for embedded ICC or other explicit non-v1 profile metadata and `embedded_raster_hdr_unsupported` for HDR metadata or high-bit-depth samples.
- Malformed marker/chunk structure remains invalid raster data rather than being upgraded to a profile limitation.
- Keep unsupported format variants that are unrelated to color under `embedded_raster_variant_unsupported`.
- Add the metadata inspection at the project-owned raster-codec boundary; advance its compatible package version if its public interface grows.
- Adding stable Diagnostic codes advances the Structured Report Schema according to the accepted versioning contract.
