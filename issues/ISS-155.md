## Description
Decide whether SVG script execution remains a permanent non-goal or may enter a future separately identified deterministic runtime profile. Define the smallest claim-safe boundary for script-created visual state without importing ambient browser, clock, network, storage, device, user, or host state into the current deterministic static comparison.

This item records a product and execution-profile decision. It does not execute scripts, add a JavaScript engine, expose DOM APIs, implement events or animation, change the current static Comparison Profile, or weaken current equality and completeness claims.

## Design constraints
- Preserve the current deterministic static profile and its no-script processing semantics.
- Separate authored script presence/source differences from executed visual-state evidence.
- Account for script source, language/runtime, DOM and SVG APIs, task/microtask scheduling, time, randomness, events, animation, resources, storage, locale, device/platform state, and termination limits.
- Treat sandbox security and deterministic replay as separate obligations; one does not imply the other.
- Define how script execution would relate to later event-state and timeline decisions without pre-deciding them.
- Preserve exact failure, timeout, unsupported-API, nondeterminism, and unavailable-state outcomes; never coerce them to visual equality.
- Define canonical versus external-observation authority and the evidence layers a script runtime may produce.
- Record permanent non-goals, deferred candidates, implementation gates, and reconsideration triggers.
- Do not add product code, dependencies, public APIs, report fields, Schema changes, Diagnostics, CLI flags, fixtures, default CI work, or release assets.

- [x] Required runtime inputs, identities, API surface, scheduling, time/randomness, resource, state, and termination contracts are complete enough to reject ambient execution.
