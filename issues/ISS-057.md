## Description
Define the released Structured Report Schema registry and require every compatibility or migration case to prove both consumer dispatch and actual Schema validity.

## Design
Register every released report Schema with its file, accepted ordering policies, canonical examples, and migration cases. Share the current project Schema validator between canonical examples and compatibility tests. For each mutated report, assert an explicit valid/invalid Schema outcome in addition to accept/reject consumer behavior. Keep unknown versions and policies uninterpretable.

## Acceptance Criteria
- [x] A versioned registry lists every released report Schema and has no duplicate or untested version.
- [x] Every accepted schema version in the consumer policy maps to one checked-in Schema.
- [x] Current, legacy-optional, additive, unknown-schema, and unknown-policy cases declare Schema-validity expectations.
- [x] Compatibility results record deterministic consumer and Schema decisions.
- [x] Every released Schema identifies canonical examples and at least one current or migration compatibility case.
- [x] Upgrade documentation requires registry, example, and migration updates for future Schema releases.
