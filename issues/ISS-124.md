# ISS-124: Align Visual Resources separately from Visual Entities

## Metadata
- Type: feature
- Status: closed
- Priority: 1
- Labels: alignment, resources, entities, mediation, schema, agent
- Assignee: codex
- Created: 2026-07-15
- Updated: 2026-07-16
- External ref: none

## Description
Give every admitted Visual Resource an explicit resource-role Subject Alignment and attach every resource Atomic Difference to that alignment. Keep placed Visual Entity alignment independent so resource causes, consumer outcomes, and image placement cannot be mistaken for one subject identity.

## Design
Add `subject_role` to Subject Alignment with the same closed `entity | resource` vocabulary as Atomic Difference. Rendered shapes, groups, text, and use hosts remain entity alignments. Symbols, gradients, patterns, markers, clip paths, masks, filters, and decoded image resources receive resource alignments. Resource definitions no longer masquerade as generic source-structural entity alignments.

Use a resource-specific deterministic rule chain and basis vocabulary. Exact recursive resource semantics may match renamed definitions without using sibling order as identity; changed definitions retain authored-ID, structural-path, and stable same-kind fallbacks with explicit ambiguity. Insertions and deletions retain an empty side. Resource alignment is correspondence evidence, not proof that consumers, computed paints, or rendered pixels agree.

Attach gradient, pattern, marker, clip, mask, filter, opaque unsupported filter subtree, unused-definition, and intrinsic image Atomic Differences to the accepted resource alignment. Use the Changed Fact resource owner and family kind to resolve the attachment; child facts such as filter primitives inherit their containing resource alignment. Fail the implementation gate if any emitted `subject_role: resource` difference retains a null or entity-role alignment.

An SVG `image` has two roles: its decoded/acquired content is a Visual Resource, while its placement, transform, fitting, opacity, and final outcome belong to a Visual Entity. Emit separate resource and entity alignments even though both retain the same source reference. Route each Atomic Difference by domain/role. Existing resource-mediated entity differences for gradient/pattern/clip/mask/filter/marker consumers retain their entity alignment and Changed Fact fan-out.

Do not duplicate Atomic Differences or collapse resource and entity identity into one alignment. A Visual Event may continue to explain one resource cause together with its sole mediated entity outcome under the existing event policy; shared or unused resources retain their existing resource event. Event ownership and Cause Envelope membership must remain deterministic and complete.

Advance the module and Structured Report schema because Subject Alignment gains a required role and resource-definition bases change meaning. Archive the prior schema and canonical example, update compatibility policy, and keep renderer identity plus conformance profile unchanged unless pixel execution changes.

## Acceptance Criteria
- [x] Every current Subject Alignment declares `subject_role` as `entity` or `resource`.
- [x] Shapes, groups, text, and use hosts remain entity alignments; admitted visual definitions use resource alignments.
- [x] Resource alignment has deterministic semantic, authored-ID, path/order fallback, insertion, deletion, and ambiguity evidence.
- [x] Every emitted resource Atomic Difference has a non-null resource-role Subject Alignment.
- [x] Gradient, pattern, marker, clip, mask, filter, unsupported filter subtree, and unused-definition cases retain their resource owner.
- [x] Embedded image intrinsic/source differences use a resource alignment while placement and mediated outcome differences retain an entity alignment.
- [x] Resource-mediated entity Atomic Differences, Changed Fact fan-out, Visual Events, Difference Regions, and Cause Envelopes remain intact without duplication.
- [x] Agent guidance distinguishes resource correspondence from entity outcome identity and prohibits inferred mediation equality.
- [x] Module/schema archives, canonical examples, compatibility, mutation, adversarial, and determinism evidence cover resource-role alignment.
- [x] Relevant MoonBit, schema, compatibility, mutation, adversarial, determinism, Agent, CLI, package, release, renderer, and performance gates pass.

## Close Notes

Added a required `entity | resource` role to every Subject Alignment and separate resource-specific semantic, authored-ID, structural-path, stable-order, insertion, deletion, and unmatched evidence. Symbols, gradients, patterns, markers, clip paths, masks, and filters now align as Visual Resources; rendered shapes, groups, text, and use hosts remain Visual Entities. Every resource Atomic Difference is deterministically attached by resource owner, source span, and family, while existing mediated entity differences, Changed Fact fan-out, events, regions, and Cause Envelopes remain intact.

Embedded images now expose independent entity placement and resource content alignments. Intrinsic source/content/presence differences use the resource alignment, while placement and scene presence retain the entity alignment. Canonical gradient evidence demonstrates one resource cause and one entity outcome in the same event without collapsing their alignment identities.
