## Description
The analyzer currently treats every `transform` attribute as unsupported. It therefore cannot distinguish equivalent transform syntax from a real coordinate-system change, retain an exact cumulative current transformation matrix, or explain a transform inherited through a group, resource container, or nested viewport.

## Design
Implement a strict project-owned SVG transform-list parser following [CSS Transforms Level 1](https://www.w3.org/TR/css-transforms-1/#svg-transform) and retain exact authored facts with Source Spans. Support `matrix`, `translate`, `scale`, `rotate`, `skewX`, and `skewY`, including compact numeric syntax and post-multiplication in authored list order. Keep dependency transform types private.

Build a source element transform inventory and accumulate local matrices from the comparison viewport through every ancestor to each encountered element. Generic `transform` participates in entity, group, resource-container, and nested-`svg` ancestry. `gradientTransform` and `patternTransform` are parsed as resource-local transform lists, but their complete resource-unit, reference, and paint semantics remain guarded by the existing resource coverage boundary.

Attach transform evidence after the selected source analyzer so inherited-fill and other specialized report paths cannot omit it. Report authored transform-list changes even when their cumulative matrices are equivalent, and report a cumulative matrix change without assigning a raw coefficient-distance score. Translation, rotation, scale, skew, and residual interpretation belongs to the next roadmap item. CSS `transform`, `transform-origin`, and `transform-box` remain in the later cascade work; `viewBox`, intrinsic sizing, and nested viewport mapping remain in the next viewport item.

Valid supported transform attributes no longer use `unsupported_visual_attribute`; malformed or incomplete transform syntax must retain a source-located limitation and cannot establish complete equality. Review the Structured Report schema, Diagnostic, ordering, renderer-conformance, and module identities under the versioning contract. Add browser-oracle fixtures before accepting complete rendered evidence for the supported basic-shape slice.

## Acceptance Criteria
- [x] A strict transform-list parser accepts every supported SVG transform function, numeric grammar, separator form, and list order while rejecting trailing or partially parsed syntax.
- [x] Equivalent authored lists normalize to the same affine matrix, and source spelling/list differences remain distinguishable from computed matrix changes.
- [x] Cumulative matrices are computed in root-to-element order for entity-local, nested-group, resource-container, and nested-viewport transforms.
- [x] One-to-one aligned supported subjects retain source-located transform Changed Facts and deterministic Atomic Differences without inventing a raw matrix-coefficient magnitude.
- [x] Group or ancestor transform changes fan out to every affected aligned subject without losing the common authored cause.
- [x] Resource-local transforms remain reportable while unresolved resource, unit, reference, and paint semantics continue to constrain coverage.
- [x] Malformed transform syntax is source-located and cannot produce complete equality; non-transform CSS and viewport semantics remain outside this item.
- [x] Browser-oracle and pinned-renderer fixtures establish or guard rendered transform evidence for the admitted basic-shape slice.
- [x] Current contracts, canonical examples, mutation/adversarial/Agent fixtures, compatibility artifacts, and all affected version identities describe the implemented boundary.
- [x] Relevant MoonBit and repository validation gates pass.

## Notes
- Matrix equality is exact over the normalized `Double` results produced from valid SVG numbers. Any future tolerance policy must be explicit and versioned.
- The current raw-magnitude contract rejects Euclidean distance between affine coefficients as visually meaningless. Transform decomposition and device-space displacement are separate checklist items.
