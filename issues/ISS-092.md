## Description
The analyzer currently guards every non-identity root `viewBox` and does not include root or nested SVG viewport mapping in a subject's cumulative coordinate transform. The pinned renderer may produce pixels, but a text-only agent cannot recover which viewport declaration changed, how that declaration maps user coordinates into the common Comparison Viewport, or which leaf outcomes it may affect.

## Design
Implement a strict project-owned viewport adapter following [SVG 2's equivalent viewport transform](https://www.w3.org/TR/SVG/coords.html#ComputingAViewportsTransform). Parse `viewBox`, `preserveAspectRatio`, and root or nested `<svg>` `x`, `y`, `width`, and `height` declarations with Source Spans. Support the SVG numeric grammar, unitless and `px` lengths, percentages against the nearest established viewport, the default `xMidYMid meet` policy, all nine alignments, `none`, `meet`, and `slice`. Invalid declarations remain source-located limitations; zero or negative viewport/viewBox dimensions must not produce an unsound complete result.

Keep one explicit common Comparison Viewport. For the outermost `<svg>`, the caller's profile width and height establish the rendered viewport, while authored `width` and `height` remain intrinsic declarations that can differ without changing the resolved mapping. A nested `<svg>` establishes its own viewport from resolved `x`, `y`, `width`, and `height`; its child percentage basis becomes the viewBox size when present and otherwise the resolved viewport size. Do not add a second API that independently sizes the two inputs. Automatic derivation from identical intrinsic declarations remains a future seam under ADR 0021.

Interleave each SVG element's generic transform and viewport mapping in root-to-leaf order. Keep authored `geometry.transform.list` evidence distinct, but let `geometry.transform.cumulative_matrix` and the typed transform-effect domains continue to describe the resulting root-to-subject affine mapping regardless of whether the changed cause is a transform or viewport declaration. Emit changed viewport declarations under `document.viewport`, retain one Changed Fact per authored property, and link every affected cumulative/effect difference to the viewport causes.

Add deterministic Chromium fixtures and compare the pinned renderer before promoting rendered completeness for root non-uniform, meet, slice, and nested viewport mappings. Any dependency divergence must receive a guard or adapter disposition. Review the module, Structured Report, Diagnostic, renderer-conformance, and ordering identities independently; do not increment the ordering policy unless tuple semantics change.

## Acceptance Criteria
- [x] Strict viewport parsing covers valid number/separator forms, `px`, percentages, all alignments, `none`, `meet`, and `slice`, while invalid and non-positive dimensions remain safely diagnosed.
- [x] Root viewBox mappings use the explicit Comparison Viewport and root intrinsic width/height changes remain reportable without independently changing the two raster canvases.
- [x] Nested `<svg>` resolves `x`, `y`, `width`, and `height`, establishes a new percentage basis, and interleaves its viewport mapping with generic transforms in specification order.
- [x] Every changed viewport declaration emits a deterministic `document.viewport` Atomic Difference and Changed Fact with Source Span provenance.
- [x] A changed resolved viewport mapping fans out to every affected aligned leaf through cumulative-matrix and typed component effects with complete cause references.
- [x] Computed-equivalent declaration rewrites remain distinguishable from a real mapping change, including ignored `preserveAspectRatio` without a viewBox.
- [x] Chromium and pinned-renderer fixtures establish or guard rendered evidence for root `none`, meet, slice, and nested viewport cases.
- [x] Current contracts, canonical/Agent examples, mutation/adversarial artifacts, compatibility registry, and every affected version identity describe the implemented boundary.
- [x] Automatic comparison-viewport inference, CSS sizing/cascade, physical units, object bounding-box units, and precise transform-aware localization remain outside this item.

## Notes

## Close Notes
Implemented strict root and nested SVG viewport adaptation under one explicit Comparison Viewport. `viewBox`, `preserveAspectRatio`, unitless/`px`/percentage viewport lengths, nearest-viewport percentage bases, and generic-transform interleaving now produce source-located `document.viewport` facts plus cumulative and typed leaf effects with complete cause fan-out. Invalid or unsupported declarations use `viewport_semantics_unsupported`; non-integer mappings retain exact source/computed evidence behind `renderer_viewport_raster_unproven`.
