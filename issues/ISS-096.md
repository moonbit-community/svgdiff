## Description
The engine retains authored length text but most geometry, stroke, and marker resolvers only accept unitless numbers. As a result, visually equivalent declarations such as `96`, `96px`, and `1in` cannot be classified as computed-equivalent, percentages are not consistently resolved against the nearest SVG viewport, and viewport-relative CSS units cannot be measured under the explicit Comparison Profile.

## Design
Add one strict project-owned SVG length resolver shared by every currently supported length-bearing semantic. Keep the exact authored value, declaration origin, and Source Span in Source Semantics while producing a separate canonical used value in local user units. Unitless values and `px` share the current user-unit scale. Resolve CSS absolute units with the fixed 96 CSS px per inch ratios. Resolve SVG percentages against the nearest established SVG viewport using horizontal, vertical, or normalized-diagonal directionality. Resolve `vw`, `vh`, `vmin`, and `vmax` against the explicit initial Comparison Viewport.

Apply the shared resolver to admitted basic-shape geometry, stroke width/dash lengths, nested viewport placement and size, and marker viewport/reference lengths. Thread the same viewport context through the private renderer-input normalizer so supported unit rewrites use canonical values without mutating Source Semantics. Font-relative units, dynamic/small/large viewport variants, writing-mode-relative viewport units, arithmetic functions, and environment-dependent units remain explicitly guarded until their dependencies are modeled.

- [x] Percentages resolve against the nearest SVG viewport width, height, or normalized diagonal according to property directionality, including nested viewBox contexts.

## Notes
- SVG percentages use the nearest SVG viewport in user units, while CSS viewport-percentage units use the initial containing block represented by the Comparison Profile. These are intentionally different bases.
- The normalized-diagonal percentage basis is `sqrt(width^2 + height^2) / sqrt(2)`.
- At comparison DPR `1.0`, CSS absolute units resolve through CSS px before the existing cumulative transform maps local user coordinates into device-space evidence.

## Close Notes
Implemented one strict contextual SVG length resolver for unitless values, CSS absolute units, SVG percentages, and static viewport-relative units. Basic shapes, stroke lengths, nested viewports, markers, computed differences, transform-aware magnitudes, and private renderer input now share the same canonical used values while retaining exact authored facts, origins, and Source Spans. Environment-dependent, dynamic, and arithmetic lengths remain guarded.

Added focused MoonBit regressions, four mutation cases, a canonical Schema example, ADR 0052, six unit-bearing Chromium fixtures, and four exact canonical companions. Validation passed with 275 native MoonBit tests; deterministic schema, compatibility, corpus, adversarial, mutation, agent, install, packaging, release, performance, fuzz, HTML-security, and renderer suites; and exact reproduction of the 60-case Chromium baseline (25 exact, 35 divergences).
