## Description
Make the accepted Phase 6 side-bound invariant explicit in the production localization seam. Current source subjects, clip/mask effects, and filter hosts are resolved independently per input, but several Difference Region helpers immediately accumulate both arrays into one optional bound. That behavior produces the correct union while making it difficult to prove that insertion, deletion, and movement retained the correct side before union.

Introduce a private side-typed bounds record. Every entity or effect localization helper must populate `before` and `after` independently and call one common union operation only at event-region attachment. Structured Report JSON continues to expose the conservative union; this item adds no public report fields.

## Design constraints
- `before` and `after` bounds are independently optional; `None` means absent, proven empty, or unavailable according to the existing family contract and must not be replaced with the other side.
- Movement preserves two nonempty side bounds; insertion preserves only `after`; deletion preserves only `before`.
- Clip, mask, filter, marker, group-opacity, image, and ordinary alignment helpers must not concatenate before and after collections before computing their side results.
- The final event bound remains the conservative union used to select pixel components or emit one computed-bounds region.
- Do not add public fields, change Schema `1.44`, or imply an exact mask, contribution map, visibility result, or side-specific pixel attribution.
- Preserve report bytes for all existing canonical examples.
