## Description
Decide whether canonical visual-semantic comparison of static SVG `foreignObject` content requires an embedded deterministic HTML/CSS layout engine, whether a deliberately bounded project-owned subset is viable, and which behavior must remain external browser observation. Define the exact layout, style, font, resource, namespace, viewport, security, and evidence authority boundary.

This item records an execution-profile and ownership decision. It does not parse or render foreign content, add an HTML/CSS engine, implement layout or fonts, load resources, run scripts, add a browser mode, change the current static Comparison Profile, or weaken current equality and completeness claims.

## Design constraints
- Preserve the current deterministic static profile and its `foreignObject` coverage guard.
- Separate outer SVG geometry and clipping, foreign markup/source facts, CSS computed state, box/line layout, text shaping, replaced resources, composited pixels, and causal provenance.
- Distinguish XML namespace processing from HTML parsing and DOM behavior; do not assume arbitrary descendants are HTML.
- Account for style inheritance across the SVG/foreign boundary, UA styles, cascade origins, writing modes, overflow, transforms, opacity/effects, containing blocks, device pixels, and accessibility-only content.
- Define whether general static support requires a complete engine and whether a bounded canonical subset may use a smaller project-owned evaluator without claiming general HTML/CSS equivalence.
- Keep fonts, resource bundles, color, script, interaction, animation, form/control state, media, locale, platform widgets, and external acquisition as explicit independent axes.
- Preserve malformed, unsupported namespace, missing resource, unavailable font/layout, ambiguous containment, overflow, engine divergence, limit, and ambient outcomes without coercing them to empty content or equality.
- Define canonical versus browser-observation authority and text-only Agent interpretation.
- Record rejected shortcuts, dependency/ownership criteria, implementation gates, and reconsideration triggers.
- Do not add product code, dependencies, public APIs, report fields, Schema changes, Diagnostics, CLI flags, fixtures, default CI work, or release assets.
