## Description
The generic shape analyzer currently compares authored geometry properties mostly as independent raw strings. It therefore cannot distinguish equivalent used geometry from real geometry changes for omitted defaults, rounded-rectangle radius propagation and clamping, equivalent point-list syntax, or non-rendering zero dimensions. It also does not fail safely on negative dimensions or malformed point lists.

## Design
Add a strict project-owned used-geometry adapter for `rect`, `circle`, `ellipse`, `line`, `polyline`, and `polygon`, following [SVG 2 Basic Shapes](https://www.w3.org/TR/SVG2/shapes.html). Retain every authored declaration and Source Span, but separately resolve the current unitless numeric slice into canonical used values. Use complete SVG number syntax for coordinates and point lists.

Resolve omitted coordinate values to zero. For rectangles, reject negative width, height, `rx`, or `ry`; treat zero width or height as valid non-rendering geometry; derive an omitted or `auto` radius from the other axis; and clamp used radii to half the used width or height. For circles, reject negative `r` and treat zero as non-rendering. For ellipses, reject negative radii, derive a single omitted or `auto` radius from the other, and treat either used zero radius as non-rendering. Lines retain their two endpoints and have no fillable interior. Polyline and polygon point lists accept SVG separators and compact signed/exponent numbers; empty or omitted points are valid non-rendering geometry, while an odd final coordinate is dropped for used geometry but remains a source-located error that prevents a complete claim.

Use canonical used geometry for alignment and Computed Relation while retaining authored facts for Changed Facts. A source rewrite that resolves to the same used shape must be computed-equivalent and may have zero rendered magnitude. Invalid or unsupported geometry must emit a stable source-located Diagnostic and cannot produce false complete equality. Keep percentage/physical-unit resolution, stroke outlines, line caps/joins/dashes, `vector-effect`, markers, CSS stylesheet cascade, and transform-aware precise localization in their existing later roadmap items.

## Acceptance Criteria
- [x] Strict number and point-list parsing covers SVG separators, compact signs, exponents, empty lists, and odd-coordinate recovery with Source Span diagnostics.
- [x] Omitted coordinates and dimensions resolve to the specified defaults without erasing authored presence or origin differences.
- [x] Rectangles implement negative/zero dimension behavior plus `rx`/`ry` auto propagation and half-dimension clamping.
- [x] Circles and ellipses implement negative, zero, omitted, and single-auto radius behavior.
- [x] Lines retain endpoint geometry while fill-only differences remain computed/rendered neutral because a line has no interior.
- [x] Polyline and polygon canonical used point sequences distinguish formatting-equivalent lists from real sequence changes and retain polygon closure semantics.
- [x] Invalid or unsupported basic-shape geometry cannot yield complete equality and uses a stable source-located Diagnostic.

## Notes
- Used geometry is not a visibility boolean. Zero-sized or empty shapes remain subjects with numeric geometry and can have source differences even when their rendered outcome is zero.
- The Diagnostic boundary applies to invalid geometry syntax or unsupported units, not to valid non-rendering zero geometry.
