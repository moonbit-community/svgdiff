## Description
Replace the current unsupported-pattern and resource-transform guards with deterministic static same-document pattern semantics. Model the tile coordinate system, content coordinate system, viewport mapping, recursive template references, supported child content, and every fill/stroke consumer without treating raw renderer pixels as the computed model.

## Design
Parse each `pattern` as an authored resource with `x`, `y`, `width`, `height`, `patternUnits`, `patternContentUnits`, `patternTransform`, `viewBox`, `preserveAspectRatio`, `href`/`xlink:href`, and its non-descriptive child set. Resolve missing attributes recursively from same-document pattern templates before applying initial values; direct non-descriptive children replace the inherited child set as one SVG 2 shadow-tree host, preserving declaration provenance and inherited style dependencies.

Resolve the tile rectangle per consumer in `objectBoundingBox` or `userSpaceOnUse` coordinates. Apply `patternTransform` after the implicit tile-unit mapping. Resolve pattern content through `viewBox` and `preserveAspectRatio` when present; otherwise use `patternContentUnits`, whose initial value is `userSpaceOnUse`. Record explicit no-paint semantics for zero tile width or height, and diagnose negative or unresolvable dimensions.

The complete child-content slice is the project's existing deterministic static basic-shape inventory with supported transforms, cascade/inheritance, solid sRGB paint, opacity, and admitted geometry. Child resources or semantics outside that slice remain precise partial guards. Pattern child content is interpreted under the referencing pattern host and consumer-specific content matrix; unsupported dynamic content, visible overflow, external references, invalid templates, and unsupported child semantics cannot produce a false complete equality.

Emit resource Atomic Differences for template selection, every tile/content attribute, transform list and effective matrices, viewport mapping, and supported child insertions/deletions or visual-property changes. Emit mediated `paint.fill` or `paint.stroke` outcomes for every consumer. Equivalent direct/template or unit/viewBox rewrites remain source-visible and computed-equivalent; unreferenced pattern changes remain resource-only.

## Acceptance Criteria
- [x] Pattern defaults and explicit `x`, `y`, `width`, `height`, `patternUnits`, `patternContentUnits`, and `patternTransform` resolve into deterministic tile geometry and matrices per consumer.
- [x] `viewBox` and every admitted `preserveAspectRatio` mode establish the pattern content viewport and override `patternContentUnits` as required.
- [x] Same-document `href` and deprecated `xlink:href` chains recursively inherit all specified attributes and the nearest non-descriptive child set, honoring unqualified `href` precedence and existing cycle/resource limits.
- [x] Template-derived content inherits through the referencing pattern host without rewriting cloned declaration origin or Source Span.
- [x] The admitted static basic-shape/solid-paint child slice records canonical child geometry, paint, transforms, ordering, and a deterministic content signature in the consumer-specific content coordinate system.
- [x] Zero tile dimensions produce explicit no-paint semantics; negative, malformed, unsupported-unit, unavailable-bounds, and invalid viewport inputs emit precise located Diagnostics.
- [x] Unsupported child resources, dynamic content, external references, visible overflow, and semantics outside the admitted child slice remain precise guards rather than false equality.
- [x] Resource differences enumerate every changed pattern field and supported child operation, while every affected fill/stroke entity receives a mediated computed paint outcome; equivalent rewrites and unreferenced resources are classified correctly.
- [x] The private renderer path either materializes the canonical supported pattern or retains a measured renderer-specific guard without altering authored evidence.
- [x] Focused MoonBit, mutation, canonical report, and Chromium conformance cases cover both units, transforms, viewBox modes, recursive templates, child changes, zero tiles, equivalence, multiple consumers, and guarded boundaries.
- [x] Current contracts, research, an ADR, feature coverage, compatibility/version identities, and the roadmap describe the admitted pattern scope and remaining child/resource boundaries.
- [x] Relevant MoonBit and repository validation gates pass.
