## Description
Make the complete `v1_domain_lexicographic` contract reviewable and executable for every current difference-domain family.

## Design
Retain the current policy identity and behavior: differences are compared only within the exact same domain, relevant available measurements form a descending lexicographic tuple, unavailable measurements are omitted rather than converted to zero, and exact tuple ties use stable report-local difference IDs. Document each family mapping and add whitebox and report-level tests. Do not introduce a cross-domain scalar or silently change the v1 tuple layout.

## Acceptance Criteria
- [x] Geometry, paint, presence, and rendered-response fallback tuples have explicit component order, units, and direction.
- [x] Missing measurements, exact-domain scope, and deterministic tie-breaking are specified.
- [x] Whitebox tests cover tuple construction for every family and comparator behavior.
- [x] Report-level tests cover descending magnitude and stable equal-tuple ordering.
- [x] Compatibility documentation requires a new policy ID for every component, availability, comparison, or tie-break change.
- [x] Agent guidance forbids cross-domain tuple comparison.

## Close Notes
Defined the complete `v1_domain_lexicographic` contract for geometry, paint, presence, and rendered-response fallback domains. All measurements compare descending in their named raw units, differences are comparable only inside the exact same domain and policy, unavailable values remain null and are omitted from the tuple, an equal prefix favors the longer tuple, and fully equal tuples use ascending report-local difference IDs. Domain groups retain first-occurrence order instead of acquiring an implicit cross-domain score.

Added whitebox coverage for ten current domain examples across all four construction families, missing-value behavior, comparator direction, equal prefixes, and equal arrays. Added report-level stable tie-breaking beside the existing descending-magnitude test, raising the native suite from 97 to 101 tests. Documented that any component, omission, direction, family assignment, comparison, or tie-break change requires a new policy ID, and that agents must use named raw magnitudes rather than reverse-engineering compact tuples.

Verified generated interfaces and formatting, warning-clean native checks, all 101 MoonBit tests, deterministic adversarial and compatibility suites, version and CLI integration, JSON syntax, local Markdown links, and `git diff --check`.
