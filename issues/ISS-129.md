## Description
Schema `1.39` can record one explicit opaque sRGB Perceptual Background but does not consume it. Raw premultiplied-RGBA error cannot answer how different the displayed colors are after transparency is resolved, and guessing a background would violate ADR 0022.

## Design
Add required `RenderedEvidence.perceptual_color` with an explicit `computed` or `not_computed` state. A computed `PerceptualColorMagnitude` uses method ID `delta_e_ok_changed_pixels_after_linear_srgb_background/v1` and records `sample_count` plus `mean_delta_e_ok`.

For each Visual Event, select the exact raw-different pixels already attributed to that event's Difference Regions. Convert each straight sRGB8 foreground and the declared sRGB8 background to linear sRGB, composite with `foreground * alpha + background * (1 - alpha)`, convert the resulting opaque linear sRGB color to OKLab, and measure Euclidean DeltaEOK. The arithmetic mean uses the selected changed-pixel count. Zero selected pixels produce an explicit measured zero with `sample_count = 0`; composited colors that become equal also produce numeric zero.

When the profile background is absent, use `not_computed/perceptual_background_absent`. When raw rendered evidence or the paired images are unavailable, use `not_computed/rendered_evidence_unavailable`. Do not infer visibility or importance from DeltaEOK, do not apply a just-noticeable threshold, and do not replace raw RGBA, geometry, coverage, boundary, region, equality, Diagnostic, or ordering evidence. Canvas-wide, event-region-area, p95, maximum, threshold-area, and FLIP statistics remain separate roadmap items.

Advance the module and Structured Report schema because every Rendered Evidence object gains one required state. Archive Schema `1.39` and one canonical report, update compatibility and Agent evidence, and keep renderer identity, conformance profile, and ordering policy unchanged. Schema `1.40` and module `0.5.20` are the target identities.
