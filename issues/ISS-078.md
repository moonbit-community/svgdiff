## Description
Make malformed and limited reports actionable by preserving source-role-qualified UTF-16 Source Spans on Diagnostics.

## Design
Add a project-owned `DiagnosticSourceLocation` with `source_role` (`before` or `after`) and a half-open `ReportSourceSpan`. Every current producer emits a `source_locations` array on every Diagnostic. Parser failures retain the exact `Milky2018/xml` error span. Input-anchored limitations retain the narrowest available element, attribute, or declaration span and merge locations when the same stable Diagnostic applies to both inputs. Comparison-global synthetic Diagnostics use an empty array instead of inventing source provenance.

Because adding a required field to the public `Diagnostic` record breaks MoonBit construction, increment the module to `0.3.0`. Add `source_locations` as an optional Schema `1.2` field so absence in legacy `1.0` and `1.1` reports means “not reported”; current `1.2` producers always emit it. Preserve released Schema `1.1`, canonical legacy evidence, and explicit compatibility cases.

## Acceptance Criteria
- [x] Malformed before and after inputs preserve exact parser error spans with the correct source role.
- [x] Unsupported elements, attributes, values, and renderer guards retain the narrowest available source locations.
- [x] One stable Diagnostic merges distinct before/after locations without duplicate IDs or locations.
- [x] Synthetic comparison-level Diagnostics emit an explicit empty location array rather than fabricated spans.
- [x] The public API, current Schema, canonical examples, compatibility corpus, version output, and release metadata use the new identities.
- [x] Agent and library documentation explains location roles, units, legacy absence, and empty-array meaning.

## Close Notes
Added the public `DiagnosticSourceLocation` record and required `Diagnostic.source_locations` field. Locations qualify half-open UTF-16 offsets with `before` or `after`, deduplicate exact repeats, and merge both inputs under one stable Diagnostic ID. XML failures now preserve the exact `Milky2018/xml` error span, including offsets after non-BMP characters. Preflight limitations retain element, attribute, presentation declaration, inline declaration, paint-reference, and renderer-guard locations; font and gradient diagnostics retain their source elements. Comparison-global and derived Diagnostics emit an empty array rather than fabricated provenance.

Allocated module/CLI `0.3.0` because the public record changed and Structured Report Schema `1.2` because the JSON field is additive. The field is optional in Schema so absence means “not reported,” while current producers always emit it. Archived Schema `1.1` and one canonical legacy report, registered Schemas `1.0`, `1.1`, and `1.2`, added explicit migrations and an optional-field case, regenerated seven current canonical reports, and added invalid-role and incomplete-location negative controls. Updated version output, installation, release provenance, library and Agent guidance, and the resolved dependency manifest retained by `moon info`.

Verified exact malformed before/after spans, merged unsupported-element locations, attribute/value/renderer-guard locations, generated interfaces and formatting, warning-clean native checks, all 108 MoonBit tests, CLI and install integration, seven canonical reports, seven accepted and two rejected compatibility cases, version identities, and release bundle checksums/provenance/notices.
