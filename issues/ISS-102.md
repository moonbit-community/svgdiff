## Description
The report currently canonicalizes only a few color spellings and models only the `opacity` longhand. Complete the deterministic sRGB solid-color grammar required by SVG 2, resolve the independent alpha factors that affect fill, stroke, and gradient stops, and preserve continuous numeric evidence even when the pinned rasterizer still requires an explicit conformance guard.

## Design
Add a small workspace package that strictly parses CSS Color 3 solid colors into canonical sRGB plus alpha: all extended named colors, `#rgb`, `#rrggbb`, legacy `rgb()`/`rgba()`, `hsl()`/`hsla()`, `transparent`, and `currentColor`. Retain the already admitted CSS Color 4 `#rgba` and `#rrggbbaa` extension. SVG 2 explicitly references CSS Color 3 for `<color>`; Phase 9 separately owns ICC, Display-P3, wide-gamut, HDR, and additional color-management profiles.

Recognize deprecated environment-dependent CSS2 system-color keywords but keep them guarded until a comparison profile supplies a pinned system palette. Invalid and out-of-scope color functions must not fall through to black or produce complete equality.

Resolve `opacity`, inherited `fill-opacity`, inherited `stroke-opacity`, and non-inherited `stop-opacity` as number-or-percentage alpha values clamped to `[0,1]`. A solid paint's effective alpha is its color alpha multiplied by the applicable paint opacity and, for a leaf element, element opacity. Keep group/root opacity under the later isolated-compositing roadmap item. Source facts remain unchanged; canonical colors and alpha products are computed evidence and private renderer inputs.

## Acceptance Criteria
- [x] A strict workspace color package parses every CSS Color 3 deterministic solid-color form, every extended named color, case-insensitive keywords, and the admitted alpha-hex extension without accepting malformed syntax.
- [x] Equivalent hex, named, RGB(A), and HSL(A) spellings resolve to the same canonical sRGB color and alpha while exact authored values and Source Spans remain reportable.
- [x] `transparent`, alpha-bearing colors, and `currentColor` participate in fill, stroke, color, and admitted gradient-stop computation.
- [x] `opacity`, `fill-opacity`, `stroke-opacity`, and `stop-opacity` accept numbers and percentages, clamp to `[0,1]`, use the correct inheritance rule, and retain continuous computed values.
- [x] Fill, stroke, and stop effective alpha multiply color alpha by the applicable opacity factors; leaf `opacity` remains separate from group/root isolated compositing.
- [x] Invalid colors, modern wide-gamut/device-independent functions, and environment-dependent system colors emit precise coverage Diagnostics rather than falling back silently.
- [x] The private renderer adapter materializes canonical supported sRGB colors and opacity values without changing original source evidence.
- [x] Focused MoonBit, mutation, canonical report, and Chromium conformance cases cover equivalent syntax, alpha multiplication, clamping, inheritance, invalid syntax, and guarded system/wide-gamut values.
- [x] Current contracts, research, an ADR, feature coverage, compatibility/version identities, and the roadmap describe the admitted color/opacity scope and remaining profile boundary.
- [x] Relevant MoonBit and repository validation gates pass.
