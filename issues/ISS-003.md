## Description
Extend the XML-backed Source Semantics slice from one isolated `rect` to an authored `<svg>` / `<g>` / `<rect>` hierarchy that can resolve inherited `fill` without using `mizchi/svg`. The resolved result must retain the declaration and Source Span that supplied the effective value so later comparison and Influence Provenance can distinguish authored changes from equivalent computed appearance.

## Design
Build a private source-element hierarchy from `Milky2018/xml` events and resolve the effective `fill` for every supported `rect`. Local inline style overrides a local presentation attribute, a local declaration overrides inherited fill, and an undeclared root falls back to the SVG initial fill. Keep `opacity` and geometry as local-only facts because they are not part of this inheritance slice. Record the winning declaration's owning element, origin, authored value, normalized value, and Source Span. Stylesheets, selectors, `currentColor`, paint servers, and general CSS remain unsupported and must reduce analysis coverage through Diagnostics rather than silently proving equality.

## Acceptance Criteria
- [x] Nested `<svg>` / `<g>` / `<rect>` elements are represented without relying on `mizchi/svg` types.
- [x] A rect inherits `fill` from the nearest declaring ancestor, with inline style taking precedence over presentation attributes at each element.
- [x] A local rect declaration overrides inherited fill, and an undeclared hierarchy resolves to the SVG initial fill.
- [x] Effective fill provenance identifies the winning owner element, declaration origin, exact authored value, normalized value, and Source Span.
- [x] Moving the same fill from a rect to its parent is a Source Semantics change while retaining equivalent resolved fill.
- [x] Changing an ancestor fill records the ancestor Changed Fact and the affected descendant rects needed to seed conservative Influence Provenance.
- [x] Unsupported stylesheet-driven fill produces an explicit Diagnostic and partial analysis instead of equality.
- [x] Structured Report JSON exposes inherited-fill provenance without exposing XML dependency types.
- [x] `moon info`, formatting checks, `moon check --target native --warn-list +73`, and `moon test --target native` pass apart from documented pre-existing warnings.
