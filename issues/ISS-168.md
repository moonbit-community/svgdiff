## Description
Validate the first terminal acceptance claim for the declared supported profile: every encountered visual semantic is either handled by the admitted evidence path or constrains the report through an explicit Diagnostic that prevents false completeness. Compose the current profile contract, feature inventory, centralized coverage proof, unsupported-input properties, renderer dispositions, admission failures, advanced non-goal gates, and adversarial boundary evidence without claiming complete SVG or browser support.

## Design constraints
- Scope the claim to schema `1.44`, the recorded Comparison Profile, and the implemented support contract.
- Treat the feature-coverage matrix and centralized proof obligations as authority for `complete`, `partial`, and `failed`; counts, raw pixels, and empty difference arrays cannot override them.
- Include successful evidence paths, known wider guarded slices, unsupported authored semantics, renderer gaps, malformed/resource-limit/reference-graph failures, and advanced profile boundaries.
- Preserve the distinction between finite regression evidence and the enforced contract: tests exercise the gate, while coverage proof and admission rules prevent silent completeness in production.
- Do not claim source identity, browser equivalence, future-profile equality, full SVG-standard support, or causal completeness for partial reports.
- Do not change product code, public APIs, Structured Report Schema, profile/policy identities, CLI behavior, fixtures, dependencies, default CI, or release assets unless the gate finds a separate verified defect.
