## Description
Extend the existing shape-oriented Subject Alignment inventory so a text-only Agent can follow stable correspondences for paths, groups, text subjects, visual resource definitions, and `use` hosts and instances. Preserve the current evidence boundary: an alignment is a deterministic comparison hypothesis, not proof of cross-document identity or visual equality.

## Design
Keep rendered geometry subjects and source-structural subjects as separate private inventories. Paths and rendered leaf instances reached through `use` remain in the existing normalized shape pipeline. Add source-structural entries for `g`, `text`, `use`, `symbol`, `linearGradient`, `radialGradient`, `pattern`, `marker`, `clipPath`, `mask`, and `filter` without forcing them through shape geometry or property-distance code.

Append structural alignments after existing shape alignments so existing shape IDs remain stable. Pair compatible kinds deterministically by authored-ID hint first, structural path second, and stable kind-local source order last; retain candidate counts, tie status, and uncalibrated confidence for every selection. Remaining endpoints become explicit insertions or deletions. These source-structure rules are intentionally bounded: later roadmap items add transform/rendered-geometry features and improve repeated-subject matching without IDs or source order.

Text alignment identifies the source text subject only. Font selection, shaping, layout, runs, glyphs, and rendered text evidence remain deferred and continue to make affected comparisons partial. Resource definitions receive source-structure correspondence only; resource Atomic Differences are not attached to these entity alignments, because independent Visual Resource alignment is a later roadmap item. Existing specialized opacity and compositing alignments remain valid property-specific evidence.

Add source-only coverage rows for structural alignment endpoints. Computed Appearance and Rendered Evidence are `not_applicable` unless an existing analyzer or Diagnostic supplies stronger or limited evidence. Do not add a new public report type or schema field.

## Notes
- This item does not implement text shaping, a font bundle, transform-aware correspondence, rendered-geometry-aware correspondence, or robust repeated-subject matching.
- Authored IDs and source order are deterministic hints, not authoritative identity. Ambiguity remains explicit.
- Resource differences deliberately retain `subject_alignment_id: null` until the separate Visual Resource alignment contract is implemented.

## Close Notes

Structural alignments append after rendered alignments, expose authored-ID, structural-path, or stable-kind-order evidence with explicit ambiguity and uncalibrated confidence, and retain insertion/deletion endpoints.
