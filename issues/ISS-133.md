## Description
The current `event_rendered_pareto/v1` policy is deliberately uncalibrated. The roadmap requires a reproducible calibration study against the versioned human-labeled corpus before any threshold, tier, or total cross-domain ordering can enter production output.

The existing `svgdiff-main-change-labels/1` data is an initial single-pass review over thirteen curated cases, with one top-ranked change per case and ordinal `none`/`low`/`medium`/`high` tiers. This item must determine what that evidence can and cannot support rather than fitting a production rule by assumption.

## Design constraints
- Keep raw report measurements and `event_rendered_pareto/v1` unchanged during evaluation.
- Treat labels as evaluation-only inputs and prove they never enter generated reports or Agent tasks.
- Record the exact corpus, annotation, report schema, renderer, metric, profile, and candidate-policy identities.
- Compare candidate threshold and ordering rules with the uncalibrated frontier baseline using deterministic leave-one-case-out or equally explicit sensitivity analysis.
- Separate top-event ordering quality from ordinal tier calibration; success on one does not establish the other.
- Do not publish a calibrated production policy when the corpus size, label coverage, reviewer agreement, metric availability, or sensitivity evidence is insufficient.
- If no candidate is supportable, record that negative result, the failed candidates, and the additional evidence required before retrying.

## Acceptance Criteria
- [x] A versioned calibration dataset joins human labels to production event measurements without leaking labels into reports or Agent tasks.
- [x] Candidate threshold and ordering families are explicit, deterministic, and traceable to named raw fields and profile inputs.
- [x] The study measures frontier recall, top-event ordering quality, tier prediction quality, ties/incomparability, missing evidence, and sensitivity to held-out cases.
- [x] Corpus size, class balance, metric availability, and reviewer agreement limitations are quantified.
- [x] Every candidate receives a reproducible accept or reject result with failure examples.
- [x] A decision record states whether a new calibrated production policy is justified; an accepted policy receives a new identity and full report compatibility work, while a rejected result leaves `event_rendered_pareto/v1` unchanged.
- [x] Current-contract, research, annotation, roadmap, and evaluation documentation reflect the result without presenting single-pass tiers as product truth.
- [x] Calibration, annotation, schema, Agent isolation, benchmark, and relevant project gates pass deterministically.
