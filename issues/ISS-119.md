# ISS-119: Preserve unsupported filter primitive source differences

- Status: closed

## Description
Define deterministic fail-open reporting for unsupported SVG filter primitives so a text-only Agent can see every possibly visual source change even when svgdiff cannot compute that primitive's appearance. Unsupported execution must remain partial, but unknown attributes, nested elements, text, and source spelling inside the primitive must not disappear behind one unchanged Diagnostic.

## Design
Capture every direct unsupported child primitive of a `filter` as an opaque source-semantic record. The record has a stable direct-child position, local element name, resource-qualified subject ID, exact full-subtree Source Span, and byte-preserving source fact. Metadata children remain excluded as already specified. Empty elements use their complete event span; paired start/end elements extend through the matching end tag, so nested primitive content is covered.

Align opaque primitive records deterministically by direct-child position. If either side at a position is unsupported, compare the complete subtree fact and local name as one conservative `resource.filter.primitive.source` difference. Insertions, deletions, type replacements, attribute changes, nested-content changes, whitespace, namespace spelling, and comments inside the captured subtree therefore remain observable. Position-based shifts may over-report subsequent records; this is intentional because unknown primitive semantics do not justify a stronger correspondence claim.

Opaque differences expose exact before/after facts and affected filter consumers, remain source-only, have an indeterminate computed relation tied to the existing filter Diagnostics, and receive no invented numeric magnitude or rendered region. Existing admitted `feOffset` pairs retain their finer graph/offset differences. Any unsupported primitive keeps the filter event partial and prevents causal-completeness or rendered-evidence claims.

Bound retained source evidence through the existing document/input limits rather than adding a second copy of subtree text. Record the fact as a span into the input and materialize its value only in the report structures already required for source evidence.

## Acceptance Criteria
- [x] Empty and paired unsupported direct primitives retain their complete source subtree, exact span, local element name, and deterministic position-qualified subject ID.
- [x] Attribute, type, source-spelling, nested-element, text, comment, insertion, and deletion changes inside unsupported primitive subtrees produce source-semantic Atomic Differences.
- [x] Position-based alignment is deterministic and conservative; shifted unknown primitives may over-report but cannot erase a changed subtree.
- [x] Unsupported primitive differences use `resource.filter.primitive.source`, exact before/after facts, affected consumers, no numeric magnitude, and only the `source_semantics` evidence layer.

## Notes
- This item deliberately accepts false positives for byte-level changes inside unknown primitive subtrees. It does not claim that such changes are visible.
- Metadata children remain outside visual differences; malformed XML remains an input failure rather than an opaque primitive record.
- Implementing additional primitive semantics later replaces opaque records with finer typed facts only when the new path proves equivalent or stronger source coverage.
