# ISS-135: Define query-conditioned handling for spatially small semantic concerns

## Description
The context-free Impact Assessment may legitimately omit a spatially small event from its Pareto frontier when a larger event dominates every available visual-magnitude measurement. A caller may nevertheless care about that event because of external task context, such as a status indicator, branding mark, or safety symbol.

The product must preserve this distinction: visual magnitude is report evidence, while semantic concern is query-conditioned context supplied by the caller. A dominated event that matches a caller concern must remain discoverable and attributable from the complete report and Agent transport, but svgdiff must not infer business importance from authored identifiers, source wording, or visual size.

## Design constraints
- Keep `event_rendered_pareto/v1` as the context-free Impact policy and retain its domination witnesses.
- Never use Impact membership, pixel thresholds, or spatial extent to delete differences from the full inventory.
- Require Agent consumers to inspect all events and atomic differences before using the Impact frontier as a main-change summary.
- Treat semantic concern as external query context, not an intrinsic Structured Report property.
- Do not infer concern or importance from authored IDs, element names, text, source order, color names, or difference counts.
- A missing caller concern means semantic importance is unknown, not low.
- Do not add speculative concern fields or change Schema, report bytes, module version, or policy identity in this item.
