## Description
The roadmap permits SSIM and MS-SSIM only as secondary structural diagnostics. The project needs a reproducible evaluation that applies named algorithm configurations to controlled SVG rasters, quantifies scale and renderer-coverage failure modes, and decides whether either metric deserves any development-QA role.

This item evaluates the metrics; it does not add them to Structured Report, Difference Magnitude, equality, Impact Assessment, Agent tasks, or release acceptance.

## Design constraints
- Follow the original SSIM local-statistics formula and the five-level MS-SSIM product weights under explicit versioned method identities.
- Record grayscale conversion, alpha compositing background, Gaussian window, constants, scale pyramid, downsampling, renderer, conformance profile, and fixture hashes.
- Use the existing pinned renderer only as a QA raster source and preserve every renderer capability limitation; a score cannot repair or override missing raster coverage.
- Compare canonical-size SSIM with enlarged-raster SSIM and MS-SSIM so scale sensitivity is observable rather than hidden.
- Retain exact-equivalent, zero-contribution, geometry, paint, structural, resource, and unsupported cases.
- Treat global pooling as non-localizing and non-causal. Do not fit severity thresholds or reuse human tiers as product labels.
- Keep the implementation evaluation-only and dependency-free beyond the existing MoonBit workspace and Python standard library.

## Notes
