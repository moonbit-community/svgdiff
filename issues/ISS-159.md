## Description
Define a versioned explicit resource-bundle abstraction for external SVG, CSS, font, image, and future host-language assets beyond current embedded data URLs and exact-locator PNG/JPEG `image` entries. Specify URL/base resolution, per-side snapshots, recursive closure, media metadata, redirects and provenance, resource identity, failure semantics, limits, and the boundary between offline prefetch and comparison-time zero I/O.

This item records an input and acquisition boundary. It does not load a new resource family, normalize existing opaque raster locators, fetch a URL, read an SVG-authored filesystem path, add a prefetch command, change current `ResourceBundle`, add decoders, alter the Comparison Profile, or weaken current equality and completeness claims.

## Design constraints
- Preserve current data-URL and exact opaque locator behavior for admitted PNG/JPEG `image` consumers.
- Keep authored locator text and Source Span, URL resolution, logical response identity, exact bytes, content interpretation, retrieval provenance, and consumer-specific computed/rendered evidence distinct.
- Define the document/base URL and nested-resource base rules without using current working directory or local path inference.
- Allow the same resolved URL to map to different exact bytes on before and after; keep snapshots side-qualified.
- Define redirect, fragment, query, origin/CORS/fetch-mode, MIME/charset, response status, integrity, cache, credential, and failure evidence required for a closed snapshot without performing those operations during comparison.
- Require recursive closure for admitted nested SVG, stylesheet, font, image, and future foreign-content graphs; preserve missing, unused, duplicate, conflicting, cyclic, depth, and budget outcomes.
- Separate a rendering-relevant fingerprint from acquisition provenance and legal/security metadata where appropriate.
- Keep network-backed acquisition a future explicit prefetch artifact with no authority to execute inside the comparison process.
- Define canonical versus external acquisition/observation authority and text-only Agent interpretation.
- Record compatibility, security, resource limits, dependency ownership, rejected shortcuts, and implementation gates.
- Do not add product code, dependencies, public APIs, report fields, Schema changes, Diagnostics, CLI flags, fixtures, default CI work, or release assets.
