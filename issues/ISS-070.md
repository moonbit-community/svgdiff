## Description
Expose machine-readable evidence, ambiguity, and confidence availability for every Subject Alignment without turning a deterministic tie-break into false certainty.

## Design
Add an `AlignmentEvidence` record to current producer alignments. Record score kind, nullable selected score, compatible candidate count, equal-score candidate count, ambiguity status, nullable confidence, and confidence status. Exact and local minimum-distance matches report conservative local ties; structural and unmatched rules report ambiguity not assessed. Confidence remains null and explicitly not calibrated. Allocate Schema `1.1` for the additive JSON field and module `0.2.0` for the required public MoonBit record field, retain Schema `1.0` and a canonical legacy report, and keep the JSON field optional so absence has the explicit meaning “not reported.” Current producers always emit it.

## Acceptance Criteria
- [x] Public MoonBit alignments expose the complete evidence record.
- [x] Current JSON reports and Schema describe all evidence, ambiguity, and confidence fields.
- [x] Exact-signature and equal-distance ties emit `tied` with reviewable candidate counts.
- [x] Unique local matches emit `unique`; structural and unmatched rules emit `not_assessed`.
- [x] Confidence serializes as null with `not_calibrated` rather than an invented score.
- [x] Canonical examples, compatibility tests, and Agent guidance cover the additive field.

## Close Notes
Added public `AlignmentEvidence` to every current Subject Alignment and exported it through the root package. Exact-signature and property-distance selection retain nullable scores, conservative local candidate and equal-score counts, and explicit `unique` or `tied` status. Structural, unmatched, and group-specific alignments report `not_assessed`. All current paths serialize `confidence: null` with `confidence_status: "not_calibrated"`.

Allocated module `0.2.0` because the public MoonBit record changed, and Structured Report Schema `1.1` because the accepted versioning contract forbids silently extending `1.0`. Preserved the released `1.0` Schema and a canonical legacy production report, registered both versions, and added deterministic cases for `1.0` migration and optional evidence absence under `1.1`. Current canonical examples validate complete evidence and reject malformed evidence records.

Documented that candidate counts and `unique` describe only the selected local scoring row, not authoritative cross-document identity or every globally optimal assignment. The text-only Agent guide explicitly forbids deriving probability from counts or treating absent evidence as uniqueness.

Verified generated interfaces and formatting, warning-clean native checks, all 105 MoonBit tests, seven canonical Schema reports, both released Schema migrations, deterministic adversarial and mutation suites, report-local reference determinism, the Agent harness, benchmark and evaluation metrics, renderer conformance and alternate-scale QA, CLI/install/completion/version/release-bundle workflows, local Markdown links, JSON syntax, and `git diff --check`.
