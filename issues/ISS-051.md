## Description
Add a versioned corpus that exercises consumer dispatch across current, legacy-additive, future-additive, unknown-schema, and unknown-ordering-policy report variants.

## Design
Generate one real current report through the production CLI, then apply reviewable manifest mutations in memory. A versioned compatibility policy classifies each variant before semantic interpretation. Accept current `1.0`, older `1.0` reports that omit later optional coverage and renderer metadata, and unknown additive top-level fields; reject unknown schema and ordering-policy identities. Run twice and hash every variant to prove determinism.

## Acceptance Criteria
- [x] The corpus base is a real current report generated by the production CLI.
- [x] Current schema and ordering policy are accepted.
- [x] Legacy schema `1.0` reports without later optional fields are accepted explicitly.
- [x] Unknown additive top-level fields are accepted without changing known semantics.
- [x] Unknown schema versions are rejected before interpretation.
- [x] Unknown ordering policy IDs are rejected before ranking.
- [x] The manifest, compatibility policy, results, and double-run gate are versioned and deterministic.
- [x] Documentation states that the corpus is not a replacement for full JSON Schema validation.
