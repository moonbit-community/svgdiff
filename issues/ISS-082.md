## Description
Define reproducible small, medium, and large deterministic SVG workloads and enforce explicit native release CLI wall-time and peak-resident-memory budgets.

## Design
Generate fixed supported-shape workloads from a versioned manifest, build the native release CLI once, and execute each comparison in several isolated child processes. Measure wall time around the CLI process and use a fresh probe process per sample so `getrusage(RUSAGE_CHILDREN).ru_maxrss` represents only that sample's product child. Normalize Linux KiB and macOS bytes to MiB.

Gate median wall time to tolerate isolated scheduler noise and maximum observed peak RSS to retain the strongest memory sample. Budgets are generous portability and regression ceilings, not optimization targets or performance claims for arbitrary SVG. Keep stage microbenchmarks diagnostic and non-additive.

## Acceptance Criteria
- [x] A versioned manifest defines deterministic small, medium, and large workload sizes and explicit wall-time and peak-RSS budgets.
- [x] Workloads stay inside the current complete supported slice and are regenerated deterministically outside timed execution.
- [x] Every sample runs the native release CLI in an isolated measured child and validates successful complete output.
- [x] Results record raw samples, median wall time, maximum peak RSS, per-metric decisions, environment identity, and overall gate status.
- [x] Positive and synthetic negative controls prove both time and memory budgets can pass and fail independently.
- [x] Documentation states measurement units, aggregation, portability limits, and the distinction from stage and Agent-quality benchmarks.
- [x] CI, roadmap, and maintenance guidance include the budget gate.
