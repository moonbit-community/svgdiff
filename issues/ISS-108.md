## Description
Report admitted structural changes when they alter a rendered subject's computed outcome, effective resource resolution, or draw order. Preserve the visual-diff boundary: an XML-only parent or sibling edit that has no admitted visual consequence remains outside Atomic Differences and belongs to the later optional source-only audit path.

## Design
Attach one consequence-aware structural pass after the existing property, inheritance, transform, viewport, instance, gradient, pattern, marker, and group-opacity passes but before Difference Regions and Cause Envelopes. Reuse one-to-one Subject Alignments and the rendered subject plan; do not create a second alignment algorithm.

Give every rendered subject a private deterministic parent-path signature. Path segments use element kind plus a same-kind sibling ordinal; authored IDs remain provenance rather than an identity oracle. Exclude the subject's own segment so ordinary sibling reordering does not masquerade as reparenting. Keep the separate use-instance definition and host path as the resource-resolution signature.

When an aligned subject's effective parent path or instance-resolution path changes, emit a structural Changed Fact only if the report already contains an admitted computed-appearance, transform, viewport, or resource-resolution consequence for that alignment. Add a `document.structure.ancestry` or `document.structure.resource_resolution` Atomic Difference and include the structural fact in the affected consequence differences. This records the changed relationship as a possible real cause without claiming that an unchanged ancestor declaration was edited.

Detect stacking changes as pairwise order inversions among one-to-one aligned rendered subjects. Emit one `document.structure.stacking_order` Changed Fact and Atomic Difference for every inverted pair whose conservative painted bounds overlap on either side and whose final rendered images differ. Unknown bounds widen to a possible overlap rather than pruning the fact. Disjoint inversions and inversions with identical final rendering remain absent. The pair fact is a conservative cause candidate, not an exact contribution index; Cause Envelopes may therefore contain false positives while retaining the real cause.

This item covers structural consequences only across semantics already admitted by the engine. It does not implement blending, isolation, clipping, masks, filters, images, external resources, dynamic instance trees, exact contribution indices, or the next item's unified cross-resource dependency graph. An encountered unsupported feature continues to revoke complete analysis through the existing coverage proof.

## Acceptance Criteria
- [x] Rendered subjects retain deterministic private parent-path and instance-resolution signatures without changing public subject identity.
- [x] Reparenting that changes ordinary inheritance emits the computed property difference plus a linked structural ancestry Changed Fact and Atomic Difference.
- [x] Reparenting that changes cumulative transforms or admitted viewport semantics emits a linked structural ancestry difference without pretending the ancestor declaration itself changed.
- [x] Changing an admitted use-instance resolution path emits a linked structural resource-resolution difference while authored definition and instance identities remain distinct.
- [x] Every potentially overlapping pair whose aligned draw order is inverted and whose rendered output changes emits a deterministic stacking-order fact and difference.
- [x] Disjoint reorderings, overlapping reorderings with equivalent final pixels, declaration-only edits, ID renames, and formatting changes do not create structural Atomic Differences.
- [x] Structural facts participate in affected consequence differences, Difference Regions, Cause Envelopes, magnitude vectors, and deterministic domain ordering.
- [x] Unsupported or unbounded structural effects remain partial with precise Diagnostics rather than false complete equality.
- [x] Focused MoonBit, mutation, canonical report, compatibility, adversarial, and Chromium fixtures cover inheritance, transforms, use resolution, active stacking, disjoint stacking, and equivalent stacking.
- [x] Current contracts, research, feature coverage, compatibility/version identities, and the roadmap describe the admitted structural-impact semantics and remaining resource-graph boundary.
- [x] Relevant MoonBit and repository validation gates pass.
