## Description
Stylesheet rules now retain declarations, specificity, source order, and exact Source Spans, but every nonempty stylesheet remains guarded because the engine cannot determine which elements a selector applies to. The next vertical slice must supply deterministic applicability to the existing cascade seam without mixing selector traversal into cascade ordering.

## Design
Introduce a private static selector module with a compact parsed-selector representation and a flat XML document index. The index retains each element's source offset, qualified element and attribute data, parent, and preceding sibling. Matching proceeds right-to-left and supplies the already-applicable stylesheet candidates for one element to the existing cascade module.

The complete static scope covers ASCII type and universal selectors, ID and class selectors, attribute presence and exact-value selectors with unescaped quoted or identifier values, compound selectors, selector lists, and descendant, child, adjacent-sibling, and general-sibling combinators. Matching is case-sensitive under the XML SVG profile; class membership uses CSS whitespace-separated tokens. CSS escapes, namespace selectors, pseudo-classes, pseudo-elements, functional selectors, comments, at-rules, and other unsupported grammar remain incomplete and guarded.

The source and inheritance analyzers merge matched stylesheet candidates with presentation and inline candidates before selecting winners. The private renderer adapter materializes complete winners per element and removes the now-redundant stylesheet text from renderer input, so the pinned renderer observes the same accepted cascade without changing original report provenance.

## Acceptance Criteria
- [x] One private selector module parses and matches the documented static selector scope independently from cascade winner selection.
- [x] The document index retains deterministic element identity, attributes, ancestry, preceding siblings, and source offsets without relying on authored IDs.
- [x] Type, universal, ID, class, attribute presence, and exact attribute-value selectors match with XML case sensitivity and CSS class-token semantics.
- [x] Compound selectors and selector lists use conjunction and alternative semantics respectively.
- [x] Descendant, child, adjacent-sibling, and general-sibling combinators match right-to-left over the indexed XML tree.
- [x] CSS escapes, namespaces, pseudo-classes/elements, functional selectors, comments, at-rules, and malformed selector syntax remain explicitly incomplete.
- [x] Matched stylesheet declarations enter the existing author cascade with their original specificity, priority, source order, origin, and Source Span.
- [x] Presentation, inline, stylesheet specificity, stylesheet source order, and stylesheet `!important` interactions produce the correct winners.
- [x] Supported stylesheet declarations affect ordinary inherited visual properties through the existing inheritance model.
- [x] The renderer adapter materializes complete stylesheet winners without changing report provenance and leaves incomplete selector input guarded.
- [x] Focused MoonBit, mutation, canonical report, and Chromium conformance cases cover selector families and cascade interactions.
- [x] Current contracts, ADRs, evaluation artifacts, compatibility/version identities, and the roadmap describe the admitted selector scope and remaining CSS boundary.
- [x] Relevant MoonBit and repository validation gates pass.

Matched candidates now flow through the existing cascade in solid-rect, generic multi-subject, hierarchy, inherited-fill, and marker paths; unsupported grammar receives a global conservative guard.
