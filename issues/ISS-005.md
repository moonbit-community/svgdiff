## Description
The prototype currently returns an empty `complete` report when both documents parse but no scenario-specific analyzer recognizes them. That is a false equality claim for arbitrary SVG input.

## Design
Introduce explicit supported-content coverage classification. Inputs outside the implemented static subset must retain any source evidence that can be established and return `partial` with Diagnostics, or `failed` when source parsing itself fails. An empty `complete` report is allowed only after every visual subject and supported fact has been analyzed.

## Acceptance Criteria
- [x] A public-seam regression test proves an unhandled visual element cannot produce empty `complete` equality.
- [x] Malformed XML/SVG produces `failed` with a diagnostic.
- [x] Known equivalent supported SVG remains `complete` with no differences.
- [x] Targeted tests and `moon check --target native --warn-list +73` pass.
