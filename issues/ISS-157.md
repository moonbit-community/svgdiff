## Description
Define one versioned timeline and checkpoint model for future SMIL, CSS animation/transition, and script-driven dynamic observations. Specify how before and after are synchronized, how event-based and unresolved timing is represented, and how a single sampled state differs from a temporal interval comparison.

This item records a temporal semantics boundary. It does not execute animation, sample frames, run scripts, dispatch events, implement CSS animation or SMIL parsing, add a browser mode, change the current static Comparison Profile, or weaken current equality and completeness claims.

## Design constraints
- Preserve the current animation-disabled deterministic static profile and existing coverage guards.
- Separate timeline definition, time origin, declared inputs, playback state, event/action triggers, sampling checkpoints, observed target time, and rendered evidence.
- Define how SVG document time, CSS/Web Animations time, script clocks, requestAnimationFrame, interaction action ticks, and external resource readiness relate without silently treating wall time as document time.
- Keep point samples, finite sample sets, keyframe/event boundaries, and continuous interval claims as different typed questions.
- Define before/after synchronization and the behavior when durations, delays, iteration counts, event starts, or animation inventories differ.
- Preserve unresolved begin/end, pending, idle, paused, finished, infinite, negative time/rate, fill, restart, cancellation, nontermination, sampling-limit, and target-divergence outcomes.
- Keep script execution and interaction state as separate axes referenced by the timeline rather than re-enabled implicitly.
- Define canonical versus browser-observation authority and text-only Agent interpretation.
- Do not add product code, dependencies, public APIs, report fields, Schema changes, Diagnostics, CLI flags, fixtures, default CI work, or release assets.
