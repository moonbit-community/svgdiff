## Description
Run the accepted text-only benchmark with an independently executed language model rather than the deterministic evidence adapter. Pin and record the model execution profile, enforce report-only input and no tool use, validate every answer against the agent-answer schema, score all accepted dimensions, classify failures, and retain an auditable observation proving whether the M3 thresholds are met.

The deterministic `evidence_test_agent.py` remains a harness and report-extractability smoke test. It cannot satisfy this milestone by itself.

## Design constraints
- Give the evaluated model only the canonical prompt, acceptance version, case ID, and Structured Report JSON.
- Do not expose SVG source, images, filenames outside the opaque case ID, human labels, expected answers, score code, repository files, memory, web, shell, or other tools.
- Run each case in a fresh ephemeral read-only session rooted in an empty temporary directory.
- Pin model, reasoning effort, Codex CLI version, answer Schema, adapter version, and timeout in a versioned benchmark profile.
- Reject a run if the execution event log records any tool or command item.
- Validate one answer per case before scoring; invalid JSON or Schema shape is an agent failure, not silently repaired by the harness.
- Use the existing accepted corpus, hidden annotations, metric definitions, failure classification, and thresholds without tuning them after observing results.
- Record raw answers or their exact hashes, per-case metrics, aggregate metrics, threshold decisions, and failure attribution so the observation is auditable.
- Keep external model execution opt-in and outside default CI because it requires authentication, cost, network availability, and is not byte-deterministic.
- Do not change product code, Structured Report Schema, public APIs, product identities, Diagnostics, dependencies, CLI behavior, fixtures, labels, thresholds, default CI, or release assets unless a verified product defect requires a separate scoped fix.

## Acceptance Criteria
- [x] A versioned language-model benchmark profile pins the report-only isolation, model, reasoning, CLI, schema, timeout, and artifact rules.
- [x] The Codex adapter rejects malformed tasks, invalid model output, case/version mismatch, timeouts, nonzero exits, and any tool-use event.
- [x] The benchmark runner records exact profile and implementation identities plus full answer/metric/gate/failure artifacts or their integrity hashes.
- [x] All 13 accepted corpus cases receive independently generated Schema-valid answers using only Structured Report evidence.
- [x] Coverage status, equality conclusion, required Diagnostic recall, Atomic Difference recall, exact magnitude-claim recall, localization, possible-cause recall, and main-difference MRR satisfy the accepted thresholds.
- [x] Hard safety failures, invalid measurements, invalid evidence references, and unclassified failures remain zero.
- [x] Report-region overlap and report Cause Envelope recall remain independently visible rather than being credited to the model.
- [x] The deterministic evidence adapter remains the default reproducible harness test and is explicitly distinguished from the language-model observation.
- [x] Current acceptance, harness, benchmark, Agent guidance, dependency/security, and roadmap documents describe the model-run authority and limitations accurately.
- [x] The exact M3 milestone checklist item is checked only if the independent model run passes; later M3 and terminal gates remain unchecked.
- [x] Product code, Structured Report Schema, public interfaces, product identities, Diagnostics, dependencies, CLI behavior, fixtures, labels, thresholds, default CI, and release assets remain unchanged unless a verified defect requires a separate fix.
- [x] Adapter negative controls, deterministic harness gates, accepted model run, `moon info`, `moon fmt`, strict native check, and the full native suite pass.
