## Description
The existing `--agent-json` mode removes formatting whitespace but still requires a limited-context Agent to ingest the complete Structured Report as one JSON object. Add a separately versioned, line-addressable projection that partitions the canonical report into a header and ordered section-item records. Every canonical field and array item must remain exactly reconstructable; the projection is a transport view, never a second source of truth.

Use JSON Lines so a consumer can read the header first and retrieve or stream individual coverage, alignment, fact, difference, event, and Diagnostic records without loading the entire report. Keep the default and compact canonical JSON modes unchanged.

## Design constraints
- Projection identity is `svgdiff-agent-projection/1`, independent from Structured Report Schema `1.43`.
- The header retains every non-array top-level report field plus exact item counts for every canonical array section.
- Item records retain the exact canonical JSON value, section name, section index, and global sequence.
- Record order is deterministic and documented.
- Reassembling the header and every item record must produce an object exactly equal to the canonical Structured Report.
- Empty sections must remain distinguishable from truncated projection streams through header counts.
- The projection may be processed incrementally; no individual record may require the complete report context.
- Do not omit source-only differences, zero or unavailable magnitudes, Source Spans, FLIP maps, Diagnostics, Changed Facts, or Cause Envelopes.
- Keep `--agent-json` as whitespace-only compaction and reject simultaneous compact and projection output modes.
- Add the public serializer and CLI option as backward-compatible module/CLI additions; do not advance Structured Report schema, renderer, ordering, or Impact identities.
