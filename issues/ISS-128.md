## Description
ADR 0022 requires display-dependent metrics to composite both inputs over the same explicitly declared Perceptual Background and forbids guessing one. The next Phase 5 perceptual-color item is therefore blocked while the Comparison Profile can record only a transparent raw canvas.

## Design
Add nullable `perceptual_background` to `ComparisonProfile`. A present value is one normalized opaque sRGB8 color with `red`, `green`, and `blue` integer channels in `[0, 255]`. The field is absent by default. It is profile evidence only in this item: transparent-canvas rendering, equality, raw raster magnitudes, regions, Diagnostics, renderer identity, and ordering remain unchanged.

Expose `PerceptualBackground::parse_srgb` by reusing the existing deterministic solid-color parser. Accept only resolved opaque colors; reject `currentColor`, system colors, invalid syntax, and alpha below one. The CLI adds `--perceptual-background COLOR`, records the normalized value, and rejects invalid or non-opaque input before comparison. Root comparison preserves the caller-provided background while continuing to pin DPR, color interpretation, raster representation, renderer identity, and renderer-conformance identity.

Advance the module and Structured Report schema because the current producer adds one required nullable profile field. Archive Schema `1.38` and one canonical report, update compatibility and documentation, and leave perceptual color measurements for the next separate item. Schema `1.39` and module `0.5.19` are the target identities.
