## Description
The engine currently treats marker elements and marker properties as unsupported input. It cannot distinguish equivalent local marker references from real attachment changes, compute the marker vertices and orientations implied by a shape, resolve the marker viewport transform, or conservatively localize the area in which a marker can paint.

## Design
Add a project-owned marker geometry model following SVG 2 marker and path-direction rules. Retain authored `marker`, `marker-start`, `marker-mid`, and `marker-end` declarations with origin and Source Span evidence while resolving local fragment references separately. Extract referenced marker resources with exact facts for `markerUnits`, `markerWidth`, `markerHeight`, `refX`, `refY`, `orient`, `viewBox`, and `preserveAspectRatio`.

For the current deterministic static slice, resolve unitless marker viewport lengths, SVG 2 reference-point keywords and percentages when a valid viewBox supplies their basis, numeric or degree orientations, `auto`, and `auto-start-reverse`. Derive vertices from each admitted shape's equivalent path, preserve duplicate vertices required by closed subpaths and zero-length segments, and resolve automatic orientation from incoming and outgoing segment directions. Compose placement, orientation, `markerUnits`, marker viewport, reference-point, and subject transforms into explicit instance transforms.

Use the clipped marker viewport as a conservative instance envelope when default hidden overflow applies. Keep marker child paint, full marker-content cascade and inheritance, `context-fill`/`context-stroke`, external references, non-unitless lengths beyond the admitted slice, and visible overflow behind stable Diagnostics unless implemented here. Renderer observations remain independently guarded until Chromium fixtures establish the pinned renderer's behavior.

## Acceptance Criteria
- [x] Authored marker attachment and resource facts retain exact values, origins where applicable, and Source Spans.
- [x] The marker shorthand and three longhands resolve to canonical local fragment references or `none`, with longhands taking precedence.
- [x] Missing, wrong-kind, external, cyclic, malformed, or unsupported marker references emit stable source-located Diagnostics and never imply complete equality.
- [x] Marker defaults and valid unitless `markerUnits`, viewport sizes, reference points, viewBox, preserveAspectRatio, and orientations resolve canonically.
- [x] Invalid sizes, keywords, angles, reference points, viewBoxes, and unsupported units emit stable source-located Diagnostics.
- [x] Lines, polylines, polygons, basic closed shapes, and normalized paths produce the SVG 2 start, mid, and end placement sequence, including closed-subpath duplication and zero-length vertices.
- [x] Automatic orientation follows segment direction and bisector rules; `auto-start-reverse` reverses only start markers.
- [x] Instance transforms compose placement, orientation, stroke-width or user-space units, marker viewport mapping, reference point, and the subject cumulative transform.
- [x] Attachment and resource changes produce typed Changed Facts and Atomic Differences without losing authored provenance.
- [x] Conservative Difference Regions and Cause Envelopes include admitted clipped marker viewport instances when raster evidence is unavailable.
- [x] Focused pinned-renderer and Chromium fixtures establish or guard attachment roles, orientation, marker units, viewport mapping, and zero-size behavior.
- [x] Current contracts, evaluation artifacts, compatibility/version identities, and the roadmap describe the implemented boundary.
- [x] Marker child paint and cascade, context paint, external references, non-unitless marker lengths, and visible overflow remain explicitly guarded unless implemented here.
- [x] Relevant MoonBit and repository validation gates pass.
