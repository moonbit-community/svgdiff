## Description
Optimize a measured production hot path without changing comparison semantics, ordering, or serialized output.

## Design
The representative CLI median grows from approximately 35 ms at 64 subjects to 276 ms at 256 subjects. The existing region microbenchmark covers one connected-component extraction but not the later per-event local rendered-magnitude calculation. That calculation scans every viewport pixel once per event even when the event has exactly one small Difference Region, producing approximately `event_count * viewport_area` work.

When exactly one pixel region is attached, restrict iteration to its clamped rectangular bounds. This selects the same pixels as the previous full-image rectangular-membership test and retains the exact changed-pixel predicate and error formulas. Keep the existing full-image union scan for zero or multiple regions. Preserve matching, region identity, metric definitions, report order, IDs, and serialized bytes. Do not change budgets.

## Acceptance Criteria
- [x] A native release measurement isolates a concrete hot operation from the representative workload.
- [x] The retained implementation removes redundant work from that operation without changing its policy or results.
- [x] Exact, unique minimum-cost, equal-cost, split, merge, insertion, and deletion behavior remains unchanged.
- [x] Canonical and compact Structured Reports remain byte-deterministic.
- [x] Repeated native release measurements demonstrate a large end-to-end improvement without loosening budgets.
- [x] Performance documentation records the measured hot path, preserved policy boundary, and observed before/after evidence.
