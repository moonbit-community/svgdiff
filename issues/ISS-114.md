## Description
Implement static SVG container opacity as an isolated compositing operation. Replace the current source-only `group_opacity_compositing_unsupported` path with covered computed semantics, continuous magnitude, production rendering, conservative localization, and causal evidence for the admitted deterministic group slice.

## Design
Resolve non-inherited `opacity` on rendered `svg`, `g`, `symbol`, and `use` containers through the existing cascade, CSS-wide value, custom-property, percentage, and clamping machinery. Preserve the winning declaration and its original Source Span. Do not copy container opacity into descendants: render each container's ordered child content into a transparent full-canvas layer with container opacity neutralized, recursively finish nested opacity layers, multiply the completed layer alpha once, then source-over composite it into its parent.

Keep the compositor as a narrow production adapter around the pinned renderer. Reuse the parsed document's transforms, viewports, paint resources, and already normalized computed declarations; retain raw pinned-renderer conformance measurements separately. Use the upstream renderer unchanged when no non-unit container opacity is encountered. Unsupported clips, masks, filters, blend modes, embedded-image composition, and already guarded renderer families remain independent Diagnostics rather than being approximated by this item.

Report one `compositing.opacity` Atomic Difference for each aligned changed container declaration. A changed resolved opacity is `different`; source changes resolving to one clamped value are `equivalent`. Record signed and absolute dimensionless parameter deltas plus symmetric-relative magnitude. Use production composited images for rendered magnitude and Difference Regions. Bound a group event by the union of every admitted rendered descendant on both sides; widen within the group or retain a separate coverage Diagnostic when instance/resource ancestry cannot be proven.

## Acceptance Criteria
- [x] Group opacity is applied once to a completed child layer, so overlapping children differ from leaf-opacity distribution in the expected way.
- [x] Root, nested, multiple-sibling, transformed, inline, stylesheet, CSS-wide, custom-property, percentage, clamped, zero, and one-valued container opacity cases resolve deterministically.
- [x] Admitted `use`/`symbol` instances preserve instance transforms and container opacity without mutating definition identity; unsupported instance cases remain explicitly guarded.
- [x] Source-equivalent opacity spellings retain source provenance and produce an `equivalent` computed relation with measured zero rather than disappearing.
- [x] Changed computed opacity reports exact before/after values, signed/absolute dimensionless delta, symmetric-relative magnitude, and a deterministic same-domain ordering tuple.
- [x] Production rendered magnitude and Difference Regions come from isolated-layer composition, and group event localization is bounded by before/after descendant effects without unrelated scene-wide contamination.
- [x] Cause Envelopes include the group opacity fact and every conservatively relevant changed descendant or backdrop fact; unsupported transfer rules revoke completeness instead of pruning.
- [x] The raw renderer divergence receives an executable compositor disposition and a new renderer-conformance profile identity; the retired group-opacity Diagnostic and capability gap no longer appear for supported cases.
- [x] Focused tests compare exact RGBA pixels against the browser fixture, exercise nesting/overlap/backdrop/order/transforms/cascade/equivalence/regions/provenance, and prevent leaf-opacity distribution regressions.
- [x] Module, Structured Report, renderer identity, conformance, schema compatibility, scope, feature coverage, Agent, causal, ADR, roadmap, and packaging documentation describe the implemented boundary.

## Notes
- This item does not implement clipping, masking, filters, blend modes, isolation controls beyond the required opacity layer, or general embedded-raster composition.
- The compositor must use straight-alpha storage with explicit premultiplied source-over arithmetic and deterministic rounding at the RGBA8 boundary.
- A product compositor disposition supplements rather than rewrites the raw pinned-renderer baseline.
