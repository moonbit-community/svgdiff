## Description
Separate renderer-conformance failures from report-model failures and agent-interpretation failures in benchmark results, while retaining input and planned feature-coverage conditions as distinct observations.

## Design
Use a versioned policy that maps Diagnostic codes to renderer conformance, feature coverage, or input failure and maps threshold metrics to report model or agent interpretation. Record Diagnostics as observations even when they are expected; record only failed gates as regressions. Preserve unknown codes or metrics as unclassified so new failure modes cannot disappear into a default bucket.

## Acceptance Criteria
- [x] Renderer-conformance Diagnostics have a dedicated classification independent of feature coverage.
- [x] Report-layer and agent-layer threshold failures map to distinct domains.
- [x] Input failures, feature-coverage limitations, and unknown classifications remain separately visible.
- [x] Every benchmark writes a failure-attribution artifact even when the threshold gate fails.
- [x] Tests cover current feature coverage, synthetic renderer/report/agent classifications, and an actual failing empty-answer benchmark.
