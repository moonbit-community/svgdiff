## Description
Implement the inherited SVG `paint-order`, `fill-rule`, and `clip-rule` properties through the existing author-cascade and computed-value seam. Preserve authored declarations and ownership, normalize the deterministic admitted values, propagate ancestor and custom-property dependencies to affected graphics elements, and distinguish currently observable paint/fill effects from deferred `<clipPath>` resource semantics.

## Design
Treat all three properties as inherited presentation properties with CSS-wide keyword, custom-property, specificity, importance, source-order, Source Span, and dependency behavior identical to the existing inherited visual-property model.

Parse `paint-order` as `normal` or a duplicate-free unordered subset of `fill`, `stroke`, and `markers`. Expand omitted operations in the default `fill stroke markers` order and compare the active operation sequence. A source rewrite that expands to the same sequence is computed-equivalent. Ignore absent fill, stroke, or marker operations when proving an order rewrite visually inactive; retain an indeterminate relation when an active marker's ordering consequence depends on deferred marker-content semantics.

Parse `fill-rule` and `clip-rule` as `nonzero` or `evenodd`, both initially `nonzero`. `fill-rule` contributes to supported shape paint semantics when the subject has a fillable interior; no-fill and non-fillable subjects treat it as inactive. `clip-rule` is retained and inherited everywhere the cascade permits it, but only graphics elements inside a `<clipPath>` can affect clipping. Because `<clipPath>` resource construction is a later roadmap item, active clipping consequences remain guarded rather than approximated; a declaration on an ordinary referencing host is source-visible but visually inactive.

Do not implement `<clipPath>` geometry, clip-path resource references, masks, marker child paint, text, animation, or scripting in this item.
