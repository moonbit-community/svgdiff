## Description
Freeze and verify the process exit statuses for complete, partial, failed, invalid-argument, and I/O outcomes so shell and agent callers can distinguish usable reports from process failures.

## Design
Use status `0` whenever a usable complete or partial Structured Report was produced, status `1` when a failed Structured Report was produced, and status `2` when no report could be produced or delivered because the invocation or I/O failed. Preserve the stdout/stderr contract from ISS-036 and record the grouping rationale in an ADR.

## Acceptance Criteria
- [x] Complete and partial Structured Reports exit with status `0`.
- [x] A failed Structured Report exits with status `1` and remains machine-readable.
- [x] Invalid arguments, input I/O failures, and output I/O failures exit with status `2` without contaminating stdout.
- [x] Help and version informational modes exit with status `0`.
- [x] Current documentation and exact-status integration tests define the stable contract.
