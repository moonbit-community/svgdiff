## Description
Define the immutable caller-supplied font input boundary that must exist before deterministic shaping, text layout, or glyph rendering can be implemented. The contract must distinguish raw font resources, collection faces, a rendering-relevant bundle fingerprint, whole-manifest integrity, licensing evidence, and later selection/runtime identities.

This item records and tests the resource contract only. It does not select shaping or rasterization dependencies, load fonts in the comparison engine, resolve CSS families, perform fallback, shape text, lay out SVG text, render glyphs, or change current partial-analysis behavior.

## Design constraints
- Font bytes are explicit caller-supplied resources; system lookup, implicit network acquisition, environment fallback, and path identity are forbidden.
- Raw encoded bytes remain authoritative and are content-addressed before decoding; collection face indices and admitted container kinds are explicit.
- The bundle fingerprint covers only rendering-relevant contract fields. Licensing and provenance evidence has separately verifiable whole-manifest integrity so a legal-metadata correction does not masquerade as a rendering change.
- Resource order, duplicates, unknown fields, malformed hashes, missing bytes, byte-length mismatches, undeclared faces, and contract-version drift have deterministic reject behavior.
- Variable axes, named instances, family matching, fallback, shaping, layout, hinting, rasterization, and platform rendering remain separate later profiles or decisions.
- Licensing fields are evidence and caller assertions, not automated legal conclusions. Distribution remains forbidden unless every shipped resource has reviewed redistribution evidence.
- The contract must be resource-bounded and safe to validate before any font parser sees untrusted bytes.
- Do not change Structured Report, Comparison Profile, public MoonBit interfaces, current text Diagnostics, module dependencies, or release assets.
