## Description
Implement the roadmap's embedded raster-image slice without implicit I/O or false final-render claims. Decode an explicit 8-bit non-interlaced PNG and single-scan baseline JPEG data-URL subset into deterministic RGBA8 resource evidence, compare its intrinsic visual content numerically, and connect each changed resource to the authored `image` subject and conservative positioning bounds. Diagnose other valid variants instead of approximating unimplemented visual semantics.

## Design
Declare a deliberately narrower policy than a general browser URL loader. Accept only `data:` locators on `image` elements with explicit case-insensitive `image/png` or `image/jpeg` media types whose decoded bytes match the declared format. Accept RFC 2397 base64 payloads and percent-encoded byte payloads. Reject omitted or unsupported media types, invalid metadata, invalid encodings, signature mismatches, and decoder failures as source-located partial Diagnostics. Never sniff a different format, fetch a URL, read a local path, execute nested SVG, or hand an unvalidated payload to a decoder.

Use a narrow project-owned workspace codec derived from the Apache-2.0 `mizchi/image@0.1.2` implementation because a direct dependency currently compiles unusable upstream package tests. Depend on `mizchi/zlib@0.4.6` for bounded decompression without patching the package cache. Enforce URI-byte, decoded-byte, per-image dimension, per-image pixel, and cumulative decoded-pixel limits before full image allocation. PNG validation must bound decompressed scanline output from its validated IHDR instead of relying on a decoder-wide default. A limit violation fails admission with the ordinary `resource_limit_exceeded` contract; malformed or unsupported content remains partial rather than being relabeled as resource exhaustion.

Represent each admitted `image` as a private source subject with stable source identity, exact `href` Source Span, compact SHA-256 evidence for encoded bytes and normalized RGBA8 pixels, intrinsic dimensions, decoded RGBA8 data, positioning facts, and supported cumulative placement context. Align images deterministically by unique authored ID and then stable source order. Different source encodings that decode to identical dimensions and RGBA8 pixels are source-distinct but computed-equivalent. Different intrinsic dimensions or pixels produce `resource.image.*` Atomic Differences, including an intrinsic raster magnitude that cannot be confused with final-canvas Rendered Evidence. Geometry, fitting, and placement distinctions use separate image domains and conservative bounds.

The pinned `mizchi/svg@0.2.1` renderer does not composite PNG or JPEG `image` elements. Keep source and computed image evidence useful, but attach a source-located renderer-unavailable Diagnostic and leave final rendered outcome unavailable. Do not claim that intrinsic resource pixels are final-canvas pixels. Renderer ownership can change in a later item or dependency release without changing this resource policy.

## Notes
- SVG 2 requires conforming viewers to support PNG, JPEG, and SVG image files. This raster item admits PNG and JPEG only; embedded SVG remains outside the declared policy.
- The following roadmap item owns explicitly supplied local resource bundles. A local path or external URL remains a non-loaded graph locator here.
- The later missing/cyclic/invalid/unused-resource item owns cross-resource normative behavior beyond the precise data-URL failures introduced here.
- Final raster compositing needs stacking, interpolation, clipping, transforms, preserveAspectRatio fitting, opacity, and renderer conformance together. This item does not silently approximate that surface.
