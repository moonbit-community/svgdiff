# Structured Report Examples

Status: canonical schema `1.39` examples

Last verified: 2026-07-16

These reports are generated byte-for-byte by the production native CLI from curated SVG sources. They teach consumers and text-only agents how the same report shape represents:

- equivalent authored color spelling with computed equivalence and measured raster zero;
- isolated group opacity with a continuous dimensionless delta, measured source-over outcome, localized region, and conservative backdrop-aware Cause Envelope;
- a shared rectangular clip-resource movement with continuous geometry magnitude, consumer fan-out, measured pixels, effect-bounded regions, and a complete Cause Envelope;
- a shared alpha-mask resource change with independent continuous alpha magnitude, consumer fan-out, isolated rendered response, effect-bounded regions, and a complete Cause Envelope;
- a categorical blend-mode change with exact CSS declarations, resolved keywords, conservative foreground/backdrop dependencies, measured browser-matched pixels, and no fabricated parameter magnitude;
- an unsupported filter primitive source change with an exact opaque subtree fact, affected consumer, precise Diagnostics, and no computed or rendered claim;
- a text source change linked to a source-structural Subject Alignment while font-dependent evidence remains explicitly deferred;
- repeated rendered leaves and parent groups retained as tied 2:2 semantic equivalence classes without pairwise array-position identity;
- transform-reordered rectangles whose authored IDs remain paired by final device-space geometry, with bounded uncalibrated correspondence evidence and no visual differences;
- a tiny continuous geometry delta whose rendered evidence is guarded;
- a transformed scalar geometry change with exact local, CSS-pixel, viewport-relative, and entity-relative parameter scales;
- a translated solid rectangle with symmetric painted-boundary displacement and alpha-only coverage-difference measurements whose raw values are asserted;
- a salient fully covered fill change that records an explicit white Perceptual Background while leaving raw evidence unchanged;
- subject insertion and deletion with numeric presence magnitude;
- a resource-mediated linear-gradient stop change with complete source/computed semantics and partial renderer coverage;
- a radial-gradient change spanning geometry, spread, transform, stop color, and its fill consumer;
- unsupported path content that is partial and must not be read as equality;
- a raster-dimension resource rejection with an empty, non-truncated difference inventory;
- a cyclic local-reference rejection with source-role-qualified locations and no renderer invocation;
- a cyclic image-resource rejection proving that guarded resource kinds still participate in the same fail-closed dependency graph;
- a parent-group transform change with exact authored and cumulative matrices plus a typed translation effect;
- a root `viewBox` change with a `document.viewport` fact, cumulative coordinate mapping, typed scale effect, and rendered region;
- equivalent rounded-rectangle declarations with distinct authored facts, canonical used radii, zero pinned-raster change, and an explicit browser-conformance guard;
- equivalent odd/even dash-array and dash-offset declarations with retained authored facts, canonical stroke geometry, measured zero, and explicit outline/dash renderer guards;
- equivalent marker viewport declarations with retained authored facts, canonical used width, conservative marker envelopes, and explicit marker-content and renderer guards.
- equivalent absolute-unit spellings with retained authored facts, canonical local-user-unit values, and zero computed and rendered displacement.
- an inline-important declaration that beats both a presentation attribute and a later normal declaration while remaining source-visible and rendered-equivalent to its canonical winner.
- a matched ID selector whose specificity winner remains source-visible and rendered-equivalent to canonical presentation paint.
- a matched stylesheet declaration inherited from a group that retains ancestor provenance while remaining computed- and rendered-equivalent to canonical leaf-local paint.
- an inherited custom property containing `currentColor` that retains all dependency declarations while remaining computed- and rendered-equivalent to canonical leaf-local paint.
- a missing local paint server whose active solid-color fallback changes with complete source, computed, rendered, and causal evidence.
- inherited paint order and winding-rule changes that distinguish active visual differences from inactive clip-rule equivalence while retaining ancestor ownership and renderer guards.
- an active stacking-order inversion represented as a structural relationship with numeric magnitude, rendered regions, and a complete conservative cause envelope.
- an embedded PNG content change with compact locator hashes, intrinsic dimensions, resource-local pixel magnitude, conservative image bounds, and explicit absence of final-canvas evidence.
- a missing exact-match caller resource that retains both locator Source Spans and partial computed/rendered coverage without implicit path or network access.
- nonvisual title, metadata, accessibility, and custom-data changes that remain complete visual equality with no visual Atomic Differences or coverage Diagnostics.

The versioned source mapping and semantic expectations live in [`evaluation/schema-examples/manifest.v1.json`](../../evaluation/schema-examples/manifest.v1.json). Run `sh scripts/test-schema-examples.sh` to regenerate every current report in memory, validate the complete assertion vocabulary used by [`svgdiff-report.schema.json`](../svgdiff-report.schema.json), assert alignment and Diagnostic-location evidence plus the distinguishing semantics, and require byte identity with these files. Archived canonical reports remain checked in for Schemas [`1.0`](legacy-1.0-unsupported-partial-coverage.json) through `1.38`; they are not regenerated by the current producer.

Update intentional report changes with:

```sh
moon build --target native --release cmd/svgdiff
python3 evaluation/schema-examples/validate.py \
  --cli _build/native/release/build/Milky2018/svgdiff/cmd/svgdiff/svgdiff.exe \
  --update
```

The shared [project validator](../../evaluation/schema_validation.py) is not advertised as a general JSON Schema implementation. It audits the checked-in Schema and fails if a future Schema uses an unsupported assertion keyword, so new vocabulary cannot silently bypass example or compatibility validation.

[`nonvisual-source-audit.json`](nonvisual-source-audit.json) is different: it validates against the independent [`svgdiff-source-audit.schema.json`](../svgdiff-source-audit.schema.json), not Structured Report. It demonstrates source-only metadata facts and is checked by [`evaluation/source-audit/validate.py`](../../evaluation/source-audit/validate.py).
