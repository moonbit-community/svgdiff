# Structured Report Examples

Status: canonical schema `1.15` examples

Last verified: 2026-07-15

These reports are generated byte-for-byte by the production native CLI from curated SVG sources. They teach consumers and text-only agents how the same report shape represents:

- equivalent authored color spelling with computed equivalence and measured raster zero;
- a tiny continuous geometry delta whose rendered evidence is guarded;
- a salient fully covered fill change;
- subject insertion and deletion with numeric presence magnitude;
- a resource-mediated gradient change with partial renderer coverage;
- unsupported path content that is partial and must not be read as equality;
- a raster-dimension resource rejection with an empty, non-truncated difference inventory;
- a cyclic local-reference rejection with source-role-qualified locations and no renderer invocation;
- a parent-group transform change with exact authored and cumulative matrices plus a typed translation effect;
- a root `viewBox` change with a `document.viewport` fact, cumulative coordinate mapping, typed scale effect, and rendered region;
- equivalent rounded-rectangle declarations with distinct authored facts, canonical used radii, zero pinned-raster change, and an explicit browser-conformance guard;
- equivalent odd/even dash-array and dash-offset declarations with retained authored facts, canonical stroke geometry, measured zero, and explicit outline/dash renderer guards;
- equivalent marker viewport declarations with retained authored facts, canonical used width, conservative marker envelopes, and explicit marker-content and renderer guards.
- equivalent absolute-unit spellings with retained authored facts, canonical local-user-unit values, and zero computed and rendered displacement.
- an inline-important declaration that beats both a presentation attribute and a later normal declaration while remaining source-visible and rendered-equivalent to its canonical winner.
- a matched ID selector whose specificity winner remains source-visible and rendered-equivalent to canonical presentation paint.
- a matched stylesheet declaration inherited from a group that retains ancestor provenance while remaining computed- and rendered-equivalent to canonical leaf-local paint.
- an inherited custom property containing `currentColor` that retains all dependency declarations while remaining computed- and rendered-equivalent to canonical leaf-local paint.

The versioned source mapping and semantic expectations live in [`evaluation/schema-examples/manifest.v1.json`](../../evaluation/schema-examples/manifest.v1.json). Run `sh scripts/test-schema-examples.sh` to regenerate every current report in memory, validate the complete assertion vocabulary used by [`svgdiff-report.schema.json`](../svgdiff-report.schema.json), assert alignment and Diagnostic-location evidence plus the distinguishing semantics, and require byte identity with these files. Archived canonical reports remain checked in for Schemas [`1.0`](legacy-1.0-unsupported-partial-coverage.json), [`1.1`](legacy-1.1-unsupported-partial-coverage.json), [`1.2`](legacy-1.2-unsupported-partial-coverage.json), [`1.3`](legacy-1.3-unsupported-partial-coverage.json), [`1.4`](legacy-1.4-unsupported-partial-coverage.json), [`1.5`](legacy-1.5-group-transform-change.json), [`1.6`](legacy-1.6-group-transform-change.json), [`1.7`](legacy-1.7-viewport-change.json), [`1.8`](legacy-1.8-basic-shape-equivalent.json), [`1.9`](legacy-1.9-stroke-equivalent.json), [`1.10`](legacy-1.10-marker-equivalent.json), [`1.11`](legacy-1.11-length-unit-equivalent.json), [`1.12`](legacy-1.12-cascade-inline-important-equivalent.json), [`1.13`](legacy-1.13-stylesheet-selector-equivalent.json), and [`1.14`](legacy-1.14-inheritance-stylesheet-equivalent.json); they are not regenerated by the current producer.

Update intentional report changes with:

```sh
moon build --target native --release cmd/svgdiff
python3 evaluation/schema-examples/validate.py \
  --cli _build/native/release/build/cmd/svgdiff/svgdiff.exe \
  --update
```

The shared [project validator](../../evaluation/schema_validation.py) is not advertised as a general JSON Schema implementation. It audits the checked-in Schema and fails if a future Schema uses an unsupported assertion keyword, so new vocabulary cannot silently bypass example or compatibility validation.
